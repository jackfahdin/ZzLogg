# 浅色主题传播修复设计

## 目标

修复运行时由深色切换到浅色主题后，日志正文、文档页及部分辅助区域仍保留深色背景的问题，同时保持现有界面布局和用户高亮配色不变。

## 根因

- `TabbedCrawlerWidget` 始终向自定义标签栏设置 QSS。Qt 因此把整个文档标签组件标记为样式表边界，应用级调色板切换无法继续传播到其子控件。
- `AbstractLogView` 的正文使用缓存位图绘制，调色板变化时没有使缓存失效；行号和项目符号边栏还硬编码了深灰、白色。
- `CrawlerWidget` 只在 `StyleChange` 时刷新搜索提示栏的默认调色板，运行时 `PaletteChange` 后可能恢复旧主题颜色。

## 方案选择

采用最小范围的主题传播修复：

1. Fluent UI 模式下不设置旧标签栏 QSS，让 `ZzFluentStyle` 负责标签尺寸和关闭按钮；非 Fluent 回退模式保留原有 QSS。
2. `AbstractLogView` 在样式或调色板变化时使绘制缓存失效，边栏背景与文字分别改用 `AlternateBase` 和 `Text` 调色板角色。
3. `CrawlerWidget` 在调色板变化时用当前父级调色板刷新活动搜索进度条；普通状态恢复调色板继承，错误提示保留语义错误色。

不采用递归强制重置所有控件调色板，因为那会覆盖错误提示、搜索进度和用户高亮等有意设置的语义颜色；也不修改第三方 `ZzPureTools`，因为它生成的浅色调色板本身正确。

## 验证

用真实 `MainWindow`、真实日志文件和真实 `ZzFluentStyle` 做集成测试：先应用深色主题并打开日志，再切换浅色主题，断言中央日志视口的 `Base` 颜色和实际渲染像素均变为浅色，并确认 `documentTabs` 下实际的 `CrawlerTabBar` 不再形成 QSS 边界。最后运行全部测试。
