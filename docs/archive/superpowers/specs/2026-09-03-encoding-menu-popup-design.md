# 编码菜单弹出修复设计

## 问题

主窗口先创建无父对象的 `QMenu`，随后通过普通 `setParent(menuBar())` 挂载编码菜单。`QWidget::setParent()` 会重置窗口标志，使编码菜单从 `Qt::Popup` 变成普通子控件。结果是菜单中的当前选项“Auto/自动”及蓝色选中标记出现在标题栏附近，而顶层“编码”入口无法弹出选项。

## 设计

让 `EncodingMenu::generate()` 接收菜单栏父对象，并在构造 `QMenu` 时直接传入该父对象。Qt 会保留菜单的弹出语义，后续 Fluent 标题栏迁移逻辑也能继续保存正确的 `Qt::Popup` 标志。

不改变编码列表、当前编码状态、翻译文本或 ZzPureTools 的蓝色单选标记。修复后的标题栏只显示“编码”，点击后才显示“自动”“跟随系统”和具体编码选项。

## 验证

在真实 `MainWindow` 上点击编码菜单对应的顶层 action，验证菜单成为可见的弹出窗口，并确认“Auto”仍是菜单内部选项。先让该测试在现有实现上失败，再实施最小生产代码修改并运行相关 UI 测试及完整测试集。
