# 浅色与深色二态主题切换设计

## 目标

ZzLogg 只向用户提供浅色、深色两种主题。标题栏主题按钮从主题菜单入口改为直接切换按钮；设置页面同步移除“跟随系统”。首次启动以及旧配置迁移完成后，应用始终持有并持久化明确的浅色或深色模式。

## 方案

复用 ZzPureTools 已有的 `ZzTitleBarThemeInteractionMode::Toggle` 和 `themeToggleRequested()`，不修改 ZzPureTools 的默认交互，也不自建主题按钮。

ZzLogg 安装 `ZzFluentTitleBar` 时将主题交互模式设置为 `Toggle`。按钮沿用框架现有图标规则：浅色主题显示月亮，提示用户可切到深色；深色主题显示太阳，提示用户可切到浅色。标题栏原有位置、尺寸、命中区域和无边框窗口集成保持不变。

框架主题菜单仍由标题栏拥有，但 ZzLogg 只保留浅色、深色动作可见；跟随系统和高对比度动作不再向用户展示。单击按钮直接在浅色、深色之间切换并保存配置。

## 主题状态与数据流

`ZzLoggFluentShell` 负责配置标题栏交互，并把 `themeToggleRequested()` 转换为明确的下一个 `ZzThemeMode`：当前已解析主题为深色时请求浅色，否则请求深色。它只发出意图，不直接修改全局主题。

`ZzLoggUiRuntime` 继续作为主题变更的唯一执行者：接收明确的浅色或深色请求，更新 `Configuration`、立即保存配置，再调用 `ZzThemeController::setMode()`。多个窗口继续观察同一个控制器，因此一次点击会同步全部窗口。

设置页面的主题组合框只包含浅色和深色。通过设置页面修改主题时继续走现有 `MainWindow::uiThemeChanged` 路径，不改变其他选项保存逻辑。

## 默认值与旧配置迁移

配置模型保留 `UiThemeMode::System` 作为只读的旧配置迁移哨兵，但它不再出现在任何用户界面，也不会成为运行期稳定状态。

启动时，如果配置缺失、保存值为 `system` 或保存值无效，先让 ZzPureTools 按当前系统配色解析出实际的浅色或深色，然后立刻把解析结果写回 `view.themeMode`，并将控制器切换为该明确模式。此后系统主题变化不会再影响 ZzLogg。

已有 `light`、`dark` 配置保持不变。高对比度或系统主题请求即使通过程序化方式到达，也不会覆盖当前有效配置。

## 错误处理与兼容性

迁移写回沿用现有 `Configuration::save()`；不增加新的配置文件版本或存储键。旧版仍能读取迁移后的 `light`、`dark` 字符串。

若标题栏安装失败，现有错误处理保持不变。主题按钮不拥有主题状态，始终以共享 `ZzThemeController` 确认后的状态刷新，避免按钮显示与实际主题不一致。

## 验证

- 扩展 Fluent Shell 测试，验证标题栏使用 Toggle 模式、只显示浅色与深色动作，并将一次点击转换为正确的相反主题请求。
- 扩展运行时契约测试，验证按钮在浅色、深色间连续切换、所有窗口同步、配置立即持久化，并拒绝高对比度或系统请求。
- 更新设置页测试，验证主题组合框只有浅色、深色两项且保存正确。
- 更新配置测试，验证 `system`、缺失值及非法值会在运行时迁移为当前系统实际配色，已有浅色和深色值保持稳定。
- 更新 UI2 冒烟探针，使其通过标题栏切换按钮验证二态主题，不再依赖主题菜单或 System 初始状态。
