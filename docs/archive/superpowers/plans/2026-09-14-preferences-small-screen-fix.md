# Preferences 小屏幕适配修复记录

## 用户场景与原因

Windows 11，14 英寸 1920×1200，推荐缩放 150%。逻辑屏幕约 1280×800，实际可用高度还需扣除任务栏和窗口边框。旧布局初始高度 817，内容没有滚动容器，底部按钮可能在屏幕外。

## 修复

- 初始高度调整到 680，尺寸策略改为 Preferred。
- 设置页签整体放入可滚动内容区域，保留原控件、页签索引和配置保存逻辑；底部按钮独立于滚动区域。
- 首次显示按当前屏幕 availableGeometry 和原生边框尺寸限制大小并修正位置；显示后再检查一次，跨屏时重新适配。
- 页签栏属于滚动内容，滚动到底部后切换页签需要先滚回顶部；本次没有重构每个设置页面。

## 验证

- 红测试：旧版英文、中文窗口 frameGeometry 超出 availableGeometry，断言失败。
- 回归：640×500 窗口中按钮完整可见，切换所有页签和滚动不会移动按钮，Cancel 可以正常关闭。
- `QT_SCALE_FACTOR=1.5`、Windows 原生平台下，中英文×深浅色四组通过（包含初始化/清理共 6 项通过）。这是本机 Qt 缩放验证，不替代用户设备的 Windows 系统 150% 实测。
- Release 编译成功；完整 CTest 60/60 通过；独立只读审查未发现阻塞问题。
- 回归另发现依赖检查仍硬编码旧框架提交 d6b90f1，已同步至当前 gitlink 5a3ea3c，不更新子仓库、不削弱检查。
