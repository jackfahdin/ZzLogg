# 代码文本高亮

在 **查看 → 语法高亮** 中选择自动识别、纯文本、C++、Java 或 JSON。
默认按文件扩展名识别：C/C++ 的源文件和头文件、`.java`、`.json`。
普通 `.log` 文件仍显示为纯文本，可手动指定语言。每个文件的选择随会话保存。

主视图及搜索结果使用原文件的词法状态，因此搜索结果即使没有包含 `/*`
所在行，也能保留多行注释颜色。支持 C++ 原始字符串、Java 注释/字符串和
JSON 值类型。语法仅提供前景色，背景沿用现有主题；深浅主题切换时随之换色。
自定义高亮、搜索命中和选区覆盖语法颜色。

## 大文件边界

这是面向现有日志查看器的有界实现：

- 定时器分批解析，每批最多 32 行，批次间让出界面线程；批次以 3 ms 为软预算，单行词法分析不可中断。
- 按需解析前 100000 行；未知状态先显示纯文本，解析完成后自动着色。
- 单行读取最多 64 KiB，解码后最多 16384 个 UTF-16 字符。超限或读取失败时，从该行起保持纯文本，避免猜测后续注释/字符串状态。
- 一行合并后超过 128 个颜色片段时，该行显示纯文本，但继续计算下一行的词法状态。
- 颜色缓存预算约 4 MiB；每 1024 行保存一个状态检查点。解析和缓存属于每个文件，由该文件的主视图和搜索结果共用。
- 文件变化、重新加载、显示编码或 ANSI 预处理变化时重新计算。

上述限制仅影响语法着色，不限制读取、搜索、复制或已有高亮功能。

## 构建

需要原有 Qt 6.8+ 环境及 Perl。CMake 首次配置下载经过 SHA256 校验的
KSyntaxHighlighting 6.22.0 和 Extra CMake Modules 6.22.0。
该版本的上游最低 Qt 版本为 6.8，并包含 Qt 6.10+ 字面量冲突修复。
语法库静态链接，语法和主题资源内嵌，运行时不需要 KDE 桌面或网络。

离线构建可传入 `FETCHCONTENT_SOURCE_DIR_ZZLOGG_SYNTAX` 和
`FETCHCONTENT_SOURCE_DIR_ZZLOGG_ECM`，指向相应版本的完整源码目录。
来源、校验值和许可证位于 `3rdparty/licenses/KSyntaxHighlighting/`；
Windows 便携包、macOS 应用包和 Linux 安装包包含这些声明。

验证：

```sh
cmake --build <build-dir> --target ci_build
QT_QPA_PLATFORM=offscreen ctest --test-dir <build-dir> --output-on-failure
```

此次改动只做代码文本显示，不增加 Android、ADB 或 logcat 采集入口。
