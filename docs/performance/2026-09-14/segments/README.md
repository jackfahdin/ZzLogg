# 滚动耗时分解

后续见 [重绘内部耗时与计时扰动](../repaint/README.md)：已进一步定位到 LineDrawer::draw 调用范围，并完成同版本三模式扰动对照。

## 目的与范围

在前一轮滚动差异诊断后，分别计量滚动条设值、同步重绘、显式事件处理。只修改测试夹具及结果收集工具，不改生产代码，不合入 master。当前已交付程序仍为 a7f1b1d5。

## 测量方法

沿用父目录的旧新版环境、138420224 字节日志、深色主题和 1280×800 窗口。搜索完成后等待 300 ms，每轮跳转 1000 个均匀位置，每次依次执行 setValue、viewport()->repaint()、QApplication::processEvents()，分别累计 QElapsedTimer 纳秒墙钟时间。每组旧新版各热身一次，再交替测五轮；重复两组。

setValue 段包含目标位置计算、最大值读取及同步信号处理。repaint 段包含整个同步调用，不等同于纯文本绘制 CPU 时间：可能涉及内部事件处理、窗口后端刷新以及线程被调度出去的时间。events 段只覆盖显式 processEvents 调用，不能代表全部事件成本。

总计时还包括新增计时调用和累加操作，三个分段之和不必严格等于总时间。新增插桩改变了二进制与测量开销，不能将本轮与此前绝对耗时直接比较来证明优化有效。CSV 分段字段允许为空以兼容旧测试程序；本次全部样本字段存在，计算占比时只使用完整样本。

## 结果

以下为排除热身后各五轮的中位数，时间单位 ms；占比为逐样本 repaint / 三段之和的中位数。各列分别取中位数，不保证横向相加等于总耗时。

| 组别 | 版本 | 总滚动 | 设值 | 同步重绘 | 显式事件处理 | 重绘占比 |
| --- | --- | ---: | ---: | ---: | ---: | ---: |
| 第一组 | 旧版 | 2421 | 12.86 | 2393.52 | 15.03 | 98.85% |
| 第一组 | 新版 | 2419 | 12.38 | 2392.96 | 14.42 | 98.90% |
| 第二组 | 旧版 | 2416 | 13.13 | 2387.96 | 15.67 | 98.81% |
| 第二组 | 新版 | 2414 | 13.07 | 2386.84 | 14.86 | 98.84% |

两组新版总耗时中位数均比旧版少 2 ms，约 0.08%，不足以支持有实际性能差异的结论。此前约 5% 的差异未在本次带插桩实验中稳定复现；这不表示已经修复，也不能直接归因于操作系统调度。

## 验证与复现材料

- 两组共 24 次调用（含热身）全部成功；视口均为 1239×539、DPR 1.00、绘制事件 1000 次。
- 修改后的新版完整原生 UI 测试：52 passed，0 failed。
- 只读审查未发现阻塞项，旧新版计时段一致。
- 两份 results.csv 保存全部样本，manifest.json 保存二进制哈希与参数。
- baseline-segments-adapter.patch 是基于旧版 248fc7c5 的完整测试适配，使用 git apply --unidiff-zero 应用，已通过反向应用检查。
- 原始日志保留在诊断工作区 out/ui-vs/scroll-segments-1000 和 scroll-segments-1000-repeat；完整测试日志为 out/ui-vs/segments-validation.txt。

执行 tools/compare-ui-performance.ps1 前设置 ZZLOGG_SCROLL_SETTLE_MS=300、ZZLOGG_SCROLL_STEPS=1000，Runs=5，其余参数与父目录报告一致。

## 结论与后续计划

本轮约 99% 的已计分段墙钟耗时落在同步 repaint 调用期间。滚动条设值和显式事件处理不是这个合成场景的主要耗时段，但尚未定位 repaint 内部热点，也未证明存在稳定的新版本回退。

下一步建议只对重绘路径做细粒度采样，区分文本布局/绘制、缓存与像素提交开销，并增加同版本插桩开关对照以检查测量扰动。在有可复现证据前不调整生产逻辑，不以此合成跳转测试推断真实连续滚动帧率。
