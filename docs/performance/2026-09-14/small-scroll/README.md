# 单行滚动与静止缓存对照

后续见 [增量像素缓存原型](../cache-prototype/README.md)：已完成原型与像素对照，单行滚动测得约 73% 耗时下降，但正式集成和缓存失效回归尚未完成。

## 结论

已确认当前实现即使每次只向下移动一行，也会重建整个可见页文本缓存：每轮 1000 次移动，drawTextArea 调用 1000 次，LineDrawer::draw 调用 36000 次，即每步约 36 行。

位置不变时强制重绘 1000 次，drawTextArea 和 LineDrawer::draw 均未调用。静止缓存有效，缺少的是小幅纵向移动时对重叠区域的增量复用。证据已足以进入原型验证，但尚未实施优化，也未测得实际优化收益。

## 方法

基于 325c7758，复用前一轮内部计时，在临时测试夹具加入 ZZLOGG_SCROLL_MOTION：

- jump：均匀跳转到整个文件的 1000 个位置。
- line：依次将滚动条设置为 1 至 1000。
- still：保持滚动条位置为 0。

全部场景在计时前先归零、重绘并处理事件，等待 300 ms 后开始采样；每步 setValue、repaint、processEvents。断言 maximum 大于步数，避免 line 触底。本日志 2097152 行，滚动范围小于 INT_MAX，verticalScrollMultiplicator 返回 1，因此一个滚动条单位对应一个日志行。

环境沿用前轮：Windows 原生 Qt 6.11.0，Release，同一台机器、深色主题，窗口 1280×800，视口 1239×539，DPR 1.00。日志 138420224 字节，先完成 ERROR 搜索。ZZLOGG_REPAINT_PROBE=1、ZZLOGG_SCROLL_STEPS=1000、ZZLOGG_SCROLL_SETTLE_MS=300。

三模式各热身一次，再正式五轮，每次独立进程。轮次除以 3 的余数为 0/1/2 时，分别使用 jump-line-still、line-still-jump、still-jump-line 顺序。测量期间无并行构建或测试。

测试二进制 SHA256：6E8EB29BDB29D95CCDB49EED695890A6B6660F4DDA7005428D47A7B5B15D38DD。

## 结果

排除热身，时间单位 ms。累计耗时取各五轮中位数，次数在全部正式轮次中一致。

| 场景 | 总耗时中位数（范围） | 缓存生成耗时 | 文字行绘制耗时 | 缓存生成次数 | 文字行绘制次数 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 大距离跳转 | 2433（2391–2509） | 1980.06 | 1645.73 | 1000 | 35999 |
| 单行步进 | 2392（2357–2444） | 1937.25 | 1642.40 | 1000 | 36000 |
| 位置不变 | 255（253–305） | 0 | 0 | 0 | 0 |

每轮三个场景的主视图 Paint 均为 1000 次。包容计时嵌套，不可相加。单行步进时，每步新露出的内容很少，但仍绘制整页，是值得验证的优化候选。

## 不能据此推断的事情

- still 还省去了位置变化、scrollContentsBy、概览更新等工作，不能把 line 与 still 的差全部看成像素缓存可节省的时间，不能宣称已经获得约九倍加速。
- line 只经过开头约 1000 行，jump 覆盖全文件，局部性、搜索命中位置和底部状态不同；两者耗时差不能只归因于步长。
- 这是固定视口、字体、主题与合成数据下的诊断，不是真实连续滚轮帧率，也未覆盖折行、反向滚动、不同 DPI 或选择高亮。
- 前轮发现的插桩扰动与墙钟计时限制仍适用。本轮没有重新证明或解释旧新版性能差异。

## 下一阶段：增量缓存原型

不再继续重复定位同一热点，转入有正确性对照的原型验证：

1. 先建立小幅上下滚动的像素一致性测试，以现有完整重绘作为参考结果。
2. 第一版仅覆盖未折行、缓存有效、首列与尺寸不变的小幅纵向移动；复用重叠像素，只补绘新露出的行。
3. 大幅跳转、折行以及缓存失效场景继续完整重绘。检查 wrappedLinesInfo、行号、标记和选择的同步，不能只保证画面看起来正确。
4. 回归主题、字体、DPI、尺寸、水平滚动、高亮、选择及文件追加等失效条件，像素结果必须与完整重绘一致。
5. 在同版本原型开关下测小步滚动收益和大幅跳转回退，再决定是否保留并合入主线；不提前承诺加速幅度。
