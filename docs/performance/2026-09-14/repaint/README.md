# 重绘内部耗时与计时扰动

后续见 [单行滚动与静止缓存对照](../small-scroll/README.md)：已确认单行步进仍整页重绘，下一阶段转入增量缓存原型验证。

## 结论

当前合成跳转场景的主要耗时位于 LineDrawer::draw 调用，不是读取日志行或将缓存贴到视口。正式五轮中，该调用累计中位数为 1663 ms，约为总滚动时间中位数 2463 ms 的 68%。这定位了一个具体调用范围，但尚未细分其中的文字宽度计算、背景填充和 Qt 文字绘制，不能把它称为纯字形绘制 CPU 时间。

本次只诊断当前版本，不重新比较旧新版，也不证明存在版本回退。临时埋点已从源码撤回，只提交本报告、原始日志、汇总和复现补丁；master 及已交付程序不变。

## 实验设置

基于 codex/scroll-diagnostics 的 6540c470，沿用前轮 Qt 6.11.0、Windows 原生平台、Release 配置及同一台机器。138420224 字节日志、2097152 行；完成 ERROR 搜索后等待 300 ms，再均匀跳转 1000 次。窗口 1280×800，主视口 1239×539，DPR 1.00，深色主题。不是连续滚轮帧率测试。

三种模式各热身一轮，再各正式五轮，每次启动新进程：

- original：未加本轮内部埋点的测试程序；保留前轮外层分段计时。
- off：已插桩二进制，ZZLOGG_REPAINT_PROBE=0，不读取内部计时器。
- on：同一已插桩二进制，ZZLOGG_REPAINT_PROBE=1，开启内部计时。

偶数轮按 original/off/on，奇数轮按 on/off/original 顺序执行。off 始终位于中间，顺序未完全随机化，因此这只是扰动观察，不是精确的开销校准实验。

## 总耗时与扰动

以下排除热身，单位 ms。

| 模式 | 总滚动中位数 | 范围 |
| --- | ---: | ---: |
| original | 2429 | 2415–2444 |
| off | 2445 | 2413–2534 |
| on | 2463 | 2426–2572 |

on 比 original 中位数高 34 ms（约 1.4%），比 off 高 18 ms（约 0.7%）。样本范围重叠，包含运行波动；off 仍有条件检查和代码布局变化。不能将差值当作精确计时器成本扣除，也不能据此解释此前的新旧版本差异。

## 内部分解

on 模式正式五轮的中位数，单位 ms。所有内部范围都是嵌套、包容的墙钟时间，不能相加。

| 范围 | 累计中位数 | 每轮调用次数 | 包含内容 |
| --- | ---: | ---: | --- |
| 外层同步 repaint | 2433.43 | 1000 | Qt 同步重绘调用 |
| paintEvent | 2044.14 | 1000 | 主视图绘制事件，含 painter 析构 |
| drawTextArea | 2000.66 | 1000 | 生成整页文本像素缓存，含读取行、背景、文字、行号和标记 |
| getLines | 14.76 | 1000 | 获取可见行 |
| LineDrawer::draw | 1663.25 | 35999 | 分块宽度计算、背景填充、文字绘制 |
| drawPixmap | 39.35 | 1000 | 把文本缓存贴到视口，不含所有后端呈现成本 |

内部计时覆盖滚动循环期间目标主视图的调用，包括可能由显式 processEvents 引发的绘制，不是严格按 repaint 调用栈过滤。本次各轮 Paint 计数均为 1000，与跳转次数相同。

repaint 与 paintEvent 的差不能直接命名为窗口刷新或 GPU 提交：它也可能包含 Qt 派发、其他组件绘制、计时操作及调度等待。Cache 扣除 Text 和 Fetch 的剩余部分也只是未单独覆盖的代码，尚不能继续归因。

## 源码解释与优化优先级

src/ui/src/abstractlogview.cpp 中，paintEvent 在首行或首列变化、缓存失效时调用 drawTextArea。虽然计算了 deltaY，但当前重新生成文本缓存仍调用整页绘制，没有利用小幅纵向位移复用重叠区域。

本次是大距离跳转，每次整页刷新合理，不能把 1000 次缓存重建当作缓存失效 bug。读取可见行约 15 ms，相比文字行绘制不是本场景的首要优化对象；也没有证据支持优先修改主题框架或滚动条样式。

下一阶段应优先建立“小步纵向滚动”的同版本对照，验证移动一行时是否仍重画整个可见页。如果证实可获益，再试验滚动像素缓存、只补画新露出的行；必须覆盖高亮、选择、行号、换行、字体、DPI、主题、文件追加和窗口尺寸变化的缓存失效条件。大距离跳转保留整页重绘，不先替换整套文字渲染方案。

## 验证与复现

18 次基准调用（含热身）全部退出 0，搜索及绘制断言通过，原始日志见 logs/，数据见 results.csv。插桩程序完整原生 UI 测试 52 项通过，0 项失败；撤回埋点后重新构建成功，再次完整测试也是 52 项通过、0 项失败。源码与测试文件相对 HEAD 无差异。只读审查未发现阻塞项，并按审查意见保留嵌套计时和扰动限制。

probe.patch 包含所有临时源码修改及新增头文件，基于 6540c470，使用 git apply --unidiff-zero 应用；已验证插桩状态下反向检查通过、撤回后正向检查通过。它仅用于隔离诊断构建，不应应用到发布构建。

复现步骤：

1. 在隔离工作区构建 zzlogg_application_translation_test Release，保存未插桩 exe 于同一输出目录，保证资源相同。
2. 应用 probe.patch，重新构建同一测试目标。
3. 设置 Qt bin 的 PATH、QT_PLUGIN_PATH；设置 ZZLOGG_SCROLL_SETTLE_MS=300、ZZLOGG_SCROLL_STEPS=1000、QTEST_FUNCTION_TIMEOUT=120000。
4. 按上述轮次顺序设置 ZZLOGG_REPAINT_PROBE，运行对应 exe 的 opensAndSearchesLargeLog -platform windows -o 输出路径,txt。不要与其他构建或测试并行。
5. 排除第 0 轮热身，统计其余五轮。完成后在隔离工作区撤回补丁并重新构建，避免误用诊断程序。

临时埋点头文件仅供 GUI 线程使用；关闭时字段为 0，原始程序无字段，在 results.csv 留空，不能混为一谈。
