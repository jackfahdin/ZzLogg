# 滚动差异初步诊断

后续结果见 [滚动耗时分解](../segments/README.md)：带分段计时的两轮实验未稳定复现此前差异，约 99% 的已计分段耗时落在同步重绘调用期间。下文保留原始实验结果，不代表已确认存在稳定回退。

## 已完成交付

设置小屏修复、性能验收工具与记录、用户人工验收反馈已按线性历史集成到 master 的 a7f1b1d5。该版本在主工作区 Release 构建成功，60 项 CTest 通过，完整运行目录已更新。没有推送。

## 本次问题与实验

问题：原对照中的约 4.5%–7.6% 滚动差异，是否只是搜索结束后待处理事件的短时影响？

旧新版保持原测量环境、日志、主题与窗口。仅在测试夹具增加两个环境参数：`ZZLOGG_SCROLL_SETTLE_MS`（0–2000，默认 0）、`ZZLOGG_SCROLL_STEPS`（100–10000，默认 100）。搜索完成后，先用 QTest::qWait 处理事件 300 ms，再开始滚动计时。分别测 100 和 1000 个均匀位置跳转；等待本身不计入滚动时间。每组每版本热身一次，再交替正式测五次。

两组共 24 次调用（含热身）均退出 0，原有搜索和绘制断言通过。新生产代码为 a7f1b1d5，旧生产代码仍为 248fc7c5；Preferences 修复不会在此未打开设置窗口的场景中直接运行。二进制哈希见各 manifest。

旧版完整测试适配保存在 [baseline-probe-adapter.patch](baseline-probe-adapter.patch)，在干净的 248fc7c5 上用 `git apply --unidiff-zero` 应用。运行器使用方式不变，执行前分别设置上述两个环境变量。当前参数入口用于受控测试，非数字环境值仍会按 Qt 默认转换成 0，复现时应严格使用本报告的数值。

## 结果

| 场景 | 旧版中位数 ms（范围） | 新版中位数 ms（范围） | 中位数差 |
| --- | ---: | ---: | ---: |
| 等待 300 ms，100 次跳转 | 279（273–280） | 296（277–299） | +17 ms，约 6.1% |
| 等待 300 ms，1000 次跳转 | 2758（2729–2960） | 2902（2867–2921） | +144 ms，约 5.2% |

CSV 保留完整样本。两组 manifest 在运行时尚未包含诊断环境变量字段，环境值以本表及原始 QTest 日志中的 `Scroll probe` 行为准；工具随后补充了自动记录字段。原始日志位于验收工作区 out/ui-vs/scroll-settled-100 和 scroll-settled-1000。

## 能得出的结论

等待处理事件后差异仍出现，并在较长的滚动循环中保留，因而本次实验不支持“仅由搜索刚结束的一次性刷新造成”的解释。不能据此完全排除周期性后台事件或操作系统调度影响。

源码对照显示，248fc7c5 到 45f7fd2d 的 AbstractLogView、LogMainView、FilteredView 实现没有变化。框架样式和页面组合有变化，但没有采样证据证明其中哪一个是原因，不能把源码变化直接当作归因。

**根因尚未定位，未修改生产算法。** 下一步应做采样剖析或同版本下的页面组合/框架样式单变量对照，区分文本绘制、滚动条样式和事件派发开销，再决定是否值得优化。本次只提交测试诊断入口和证据，不合入 master、不影响已交付程序。
