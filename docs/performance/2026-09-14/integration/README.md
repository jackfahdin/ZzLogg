# 增量缓存正式实现验收

## 实现

实现提交 fb2db225。正式代码不含原型开关或内部计时器。未折行、缓存有效、首列未变、前后有完整页面且物理位移为整数的小幅纵向滚动，复用重叠像素，仅补绘露出区域与边界保护带；其他情况完整重绘。重叠行的命中测试元数据仍会重建。

同时补齐了选择/快速查找、行号、主视图搜索命中标记、字体与 DPR 变化的失效处理，修复可见列数使用旧行号边距以及分数缩放边缘像素没有完整清空的问题。上述问题在完整重绘模式也可能被掩盖，不能把原型直接作为正式版本。

## 正确性

新增独立 textcachetest.cpp，使用真实文件 LogData、共享渲染器、真实 FilteredView 和 MainWindow。验证：

- 连续上下滚动与完整重绘逐像素一致。
- 部分选择、选择跳转、快速查找清除、搜索高亮与命中标记。
- 滚动后再次点击，选中的行号和 UTF-8 中文内容正确。
- 行号、调色板、字体、尺寸、水平滚动、折行切换。
- 文件追加后重载、截断后重载、页尾以及过滤结果和标记变化。

100%、125%、150%、200% 独立原生 Qt 进程各 13 项测试通过。全量 61 项 CTest 通过（49.38 秒）。临时恢复旧版渲染器后，行号、直接字体变化、快速查找清除三个测试失败，恢复正式代码后通过，失败证据已保留。主窗口命中标记测试在旧版也通过，其失效补充依据静态调用链审查，不能声称该用例单独证明进度失效缺口。

真实跨屏 DPI 迁移没有在本轮自动化中操作；各固定缩放档位通过不能替代迁移验收。DPR 事件及绘制入口的缓存 DPR 检查均已实现，仍建议人工复核跨屏拖动。

## 无内部插桩性能对照

与 284ec024 的生产渲染器对照。两边使用相同的新测试夹具（新增 line/jump 模式），均无 drawTextArea 等内部计时埋点；保留原有外层 setValue/repaint/processEvents 分段。基线通过临时恢复 abstractlogview.cpp 和 crawlerwidget.cpp 到 284ec024 构建后保存 exe，随后恢复正式实现；没有将旧源码留在提交中。

同机 Windows、Qt 6.11.0、Release，深色主题，138420224 字节/2097152 行日志，视口 1239×539、DPR 1.00，搜索后等待 300 ms，每轮 1000 次。各模式每版本热身一次，交替顺序正式测五轮，24 次调用均通过。运行期间没有并行构建或其他测试。

| 场景 | 基线中位数 ms（范围） | 正式实现中位数 ms（范围） |
| --- | ---: | ---: |
| 单行步进 | 2398（2385–2501） | 582（575–584） |
| 大距离跳转 | 2433（2419–2534） | 2433（2418–2507） |

单行步进耗时减少约 75.7%；大跳转中位数持平。本结果只支持该合成场景，不是滚轮 FPS，也不保证分数 DPR 下总能启用增量路径。没有据此宣称此前旧 UI 框架的性能差异根因已解决。

CSV 和 manifest 保存全部数值、环境参数与二进制哈希。原始 QTest 日志保留在诊断工作区 out/ui-vs/formal-perf-line 和 formal-perf-jump。用 tools/compare-ui-performance.ps1 设置 ZZLOGG_SCROLL_MOTION=line 或 jump、ZZLOGG_SCROLL_STEPS=1000、ZZLOGG_SCROLL_SETTLE_MS=300 复现。
