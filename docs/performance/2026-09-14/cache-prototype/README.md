# 增量像素缓存原型

## 结果与交付范围

原型显示了值得继续实现的收益：同版本、同插桩二进制开关对照，1000 次单行滚动中位耗时从 2560 ms 降至 684 ms，减少约 73.3%，约为原耗时的 26.7%。大距离跳转中位数从 2531 ms 变为 2540 ms（约 +0.36%），样本重叠，本轮未见明显回退，但不能据此保证其他环境没有回退。

本次是一次性原型验证，不是可发布实现。prototype.patch 保存完整实验代码和测试，临时源码已撤回，不合入 master，不更新已交付程序。

## 方案与保护条件

在 drawTextArea 中，仅当 ZZLOGG_INCREMENTAL_CACHE=1 且满足以下条件时启用：

- 未折行，缓存有效，首列未变。
- 前后位置都具有完整可见页，移动距离小于一页。
- 物理像素位移为整数。

移动缓存 pixmap 中的重叠像素，裁剪绘制到新露出区域。重叠行仍计算文本、高亮信息并重建 wrappedLinesInfo，但跳过实际绘制；不是跳过全部逐行处理。大距离跳转、非整数物理位移及不符合条件的状态保留完整重绘。

边界额外补画 1 个逻辑像素保护带，因此单行移动通常绘制两行而非一行。原因是纵向分隔线的抗锯齿端点随缓存移动，需要清除旧端点。

## TDD 与像素对照

先编写“只绘制新露出行”的断言，旧实现以 painted 36 失败（validation/cache-red.txt）。初版原型将绘制缩减到一行，但逐像素对照发现 2 个差异像素，位于 QRect(10,524 2x1)（cache-pixel.txt）。增加逻辑像素保护带后通过，未放宽像素相等要求。

测试位置序列为 100 → 101 → 102 → 101 → 99 → 102：

1. 每个位置的原型画面与 forceRefresh 后的完整重绘逐像素比较。
2. 保存完整重绘参考图，再从 100 开始连续复用缓存走完同一序列，中途不 forceRefresh，逐图比较，检查累积误差。

默认显示、全选、隐藏行号、改变窗口尺寸、改变字体，共五种配置，在 QT_SCALE_FACTOR=1 与 1.5 下各通过一次，共 10 组，含两阶段共 100 次图像比较。DPR 1 下同时断言绘制行数不超过位移行数加一；DPR 1.5 只断言像素一致，部分步长回退完整绘制，不能声称 150% 缩放始终有同样收益。

这些配置在建立基准缓存之前设置，验证的是配置下的滚动，不等于配置变化时的失效路径已经回归。选择为全选，位置约 99–138 行不含 fixture 的 ERROR 命中，因此并未验证局部选择边界或实际搜索高亮命中。

每模式热身一次再正式五轮，每次新进程。偶数轮 jump-off/jump-on/line-off/line-on，奇数轮反序。24 次全部通过。下表排除热身：
