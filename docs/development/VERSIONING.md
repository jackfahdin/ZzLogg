# ZzLogg 版本号规则

## 产品版本

采用 `YY.MM.PP`：两位年份、两位月份、至少两位的当月修订号。
例如 `26.09.00`、`26.09.01`、`26.10.03`。新月份首版的修订号归零；
修订超过 99 时完整显示，不截断。版本仅在决定发布时手动更新，不随编译日期变化。

默认版本维护在根目录 `CMakeLists.txt` 的 `project(VERSION ...)`，使用整数形式
（如 `26.9.0`）；`cmake/ZzLoggVersion.cmake` 统一生成展示用的 `26.09.00`。
CI 的 `BUILD_VERSION` 可覆盖版本，接受三段或四段数字。
GitHub Actions 通过 `cmake/ExportCiVersion.cmake` 从同一处读取版本，导出补零后的
`KLOGG_VERSION`，使程序、CPack 以及产物文件名保持一致。

## 展示与构建信息

- 关于窗口、命令行、打包版本及 Windows 文件/产品版本文字使用 `26.09.00`。
- 标题栏只显示文件名和应用名，不追加构建号。
- 构建日期、提交短哈希单独保留在关于窗口和命令行中，用于定位具体构建。
- Windows 底层数值版本为四段整数，如 `26,9,0,0`；该字段无法保留前导零。
  `BUILD_NUMBER` 或版本的第四段仅设置底层构建号，不进入产品版本文字。
- Git 发布标签使用 `v26.09.00`；发布时再创建标签，不修改历史标签。

## 版本比较

更新检查使用 Qt 的数值版本解析，不按显示字符串排序。发布清单的版本文字应使用
相同的两位格式，以便稳定版列表匹配。当前未配置更新服务，此规则不启用网络更新。

## 验证

`zzlogg_ui.version_display` 覆盖前导零、第四段隐藏及三位修订号。
Windows 的 `zzlogg_ui.version_resource_contract` 读取真实可执行文件的版本资源，
核对文件版本与产品版本的文字格式。
