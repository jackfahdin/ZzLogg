# ZzLogg 品牌名称与应用图标设计

## 状态

设计已在 2026-08-31 经用户逐项确认。本文定义 ZzLogg 的外部品牌重命名、应用身份重置、图标资源及验证边界。

## 目标

- 将所有用户可见的产品名称统一为 `ZzLogg`。
- 将发布产物、平台元数据、配置路径和安装入口切换为新的 ZzLogg 身份。
- 以现有 klogg 图标为基础完成轻量品牌化，而不是采用根目录中的红色搜索候选图标。
- 为 Windows、macOS、Linux 和 Qt 运行时提供一致的图标资源。
- 保持现有业务实现和内部库边界稳定，避免无用户价值的全仓符号重命名。

## 非目标

- 不迁移或兼容原有 klogg 配置、会话和便携配置。
- 不批量重命名内部 `klogg_*` 库、类、宏、源码目录和测试标识。
- 不恢复默认构建 `klogg_grep`；它仍然只能显式构建。
- 不在本次工作中建立新的在线发布或更新服务。
- 根目录中的 `serach.png` 和 `serach.svg` 仅作为早期候选参考；实现不修改、不删除，也不纳入版本控制。

## 方案选择

采用“完整外部重品牌”方案：应用对用户呈现为全新的 ZzLogg 身份，但内部构建目标和源代码符号尽量保留原名。

未采用以下方案：

- 同时重命名所有 CMake 目标：会扩大脚本和测试改动，用户没有额外收益。
- 全仓替换 klogg 命名：风险和审查成本过高，且不改善产品体验。

## 产品身份

### 集中元数据

CMake 配置集中维护以下品牌数据，其他平台配置从这里派生或与其保持一致：

- 产品名：`ZzLogg`
- 描述：`ZzLogg log viewer`
- 供应方：`JackfahdinQt`
- 项目主页：`https://gitcode.com/JackfahdinQt/ZzLogg`
- 应用标识：`com.gitcode.jackfahdinqt.zzlogg`

原作者和贡献者版权声明继续保留，不因品牌变更而删除。

### 外部产物名称

内部 CMake 目标名保持不变，通过 `OUTPUT_NAME` 暴露新的文件名：

| 内部目标 | 外部产物 |
| --- | --- |
| `klogg` | `ZzLogg` / `ZzLogg.exe` |
| `klogg_portable` | `ZzLogg_portable` / `ZzLogg_portable.exe` |
| `zzlogg_ui2` | `ZzLogg_ui2` / `ZzLogg_ui2.exe` |
| `klogg_grep` | `ZzLogg_grep` / `ZzLogg_grep.exe` |

便携目录使用 `ZzLogg-portable`。安装包、快捷方式、桌面入口、文件关联和平台 Bundle 均使用 ZzLogg 名称。

### 配置身份

本次变更建立全新配置身份，不读取旧 klogg 配置：

- 普通配置：`ZzLogg/ZzLogg.ini`
- 会话配置：`ZzLogg/ZzLogg_session.ini`
- 便携配置：`ZzLogg.conf`
- 便携会话配置按现有派生规则从 `ZzLogg.conf` 生成

测试继续通过临时目录或显式覆盖路径隔离配置，禁止访问真实用户配置。

## 应用图标

### 视觉结构

图标保留现有图标的文档堆叠、日志行和放大镜结构，仅做以下修改：

- 放大镜镜片中心使用蓝色粗体小写 `z`。
- `z` 位于纸张之上、镜片染色和高光之下，并相对早期预览略微上移。
- 后方纸张的可见日志行使用蓝、红、黄、绿、紫色块，提高日志语义与层次。
- 放大镜把手使用带高光和阴影的琥珀橙染色，与蓝色镜片形成冷暖对比。
- 放大镜的镜片、高光、边框和把手作为最上层，不能被纸张色块或字母覆盖。

字母必须转换为固定矢量轮廓，不能依赖运行机器上的字体。

### 源文件与派生资源

修改后的 SVG 是唯一设计母版。派生二进制资源提交到版本库，普通构建只消费已生成文件，不要求安装额外图像转换工具。

需提供：

- Windows：包含 16、20、24、32、40、48、64、128、256 px 帧的 `ZzLogg.ico`
- macOS：包含 16、32、64、128、256、512、1024 px 表示的 `ZzLogg.icns`
- Linux：可缩放 SVG，以及 16、32、48、64、128、256、512 px PNG
- Qt 资源：使用同一 SVG 或对应平台 PNG 设置运行时窗口图标

16、32 和 48 px 不能只依赖系统自动缩放；需要逐尺寸检查 `z`、日志色块和把手的清晰度。

现有图标文件中的许可和作者元数据继续保留在 SVG 母版或相邻说明中。

## 代码接入

### 共享启动入口

旧 UI、便携目标和 UI2 通过共享应用启动入口统一设置：

- `QCoreApplication::applicationName()` 为 `ZzLogg`
- `QGuiApplication::applicationDisplayName()` 为 `ZzLogg`
- `QApplication::windowIcon()` 使用新的 ZzLogg 图标

应用标题、托盘提示、消息框标题和关于页面从统一品牌常量取得名称，避免继续散落硬编码 `klogg` 或 `Klogg`。

### 平台与打包

以下入口同步更新：

- Windows 版本资源、NSIS、便携目录、快捷方式和文件关联
- macOS Bundle 名称、标识和 ICNS
- Linux desktop 文件、图标安装路径与 CPack 元数据
- 当前仍在维护的发布脚本和包清单

历史性的第三方或上游归属文字不做机械替换；只有代表当前产品身份和发行位置的内容改为 ZzLogg。

### 外部链接和更新检查

主页和问题反馈链接改到当前 GitCode 仓库。旧的 `variar/klogg` 自动更新清单不得继续作为 ZzLogg 的更新来源。

实现时验证当前仓库是否提供可访问的 ZzLogg 更新清单：

- 若存在有效清单，更新检查指向该地址。
- 若不存在，关闭自动更新检查并保持静默，不向用户显示错误，也不建议安装上游 klogg。

## 错误处理

- 图标资源缺失或无法解析时，配置或测试阶段直接失败，不能发布无图标产物。
- 平台图标转换失败时，不覆盖已有派生资源，避免留下部分更新状态。
- 品牌元数据与平台文件不一致时，验证脚本返回失败并列出仍存在的外部 `klogg` 名称。
- 更新清单不可用时禁用检查，不影响应用启动和日志查看功能。

## 验证策略

### 自动测试

- 品牌常量与配置路径测试：验证新名称、普通配置、会话配置和便携配置。
- GUI 冒烟测试：验证应用显示名、窗口标题和窗口图标非空。
- UI2 现有标题栏与生命周期测试继续通过。
- 图标资源测试：解析 SVG，检查 PNG 尺寸与透明通道，检查 ICO/ICNS 必需表示。
- 构建产物测试：确认只生成新的外部可执行文件名，`ZzLogg_grep` 仍不在默认构建中。
- 便携目录测试：确认目录名、主程序名和运行库完整。
- 设置隔离测试：确认自动测试前后真实用户配置未变化。

### 构建验证

- Windows Qt 6 Debug 完整工作流。
- Windows Qt 6 RelWithDebInfo 完整工作流。
- 依赖检查：旧 UI 目标不依赖 ZzPureTools DLL，UI2 不依赖聚合 DLL。
- Git 差异、子模块状态和残留进程检查。

### 人工验收

- Windows 100%、125%、150%、200% DPI 下检查标题栏、任务栏和窗口图标。
- 浅色、深色和高对比度环境检查小尺寸图标。
- macOS Dock/Finder 与 Linux 桌面环境需要在对应真实主机完成最终验收。

## 完成标准

- 用户可见产品身份均为 ZzLogg。
- 新图标在 Windows、macOS、Linux 和 Qt 运行时一致。
- 新配置身份生效，旧配置不会被读取或修改。
- Debug 与 RelWithDebInfo 构建和测试通过。
- 默认构建不生成 `ZzLogg_grep`。
- 未通过真实平台验证的项目明确记录为待验收项，不宣称已经通过。
