# P12：直接 UTF-8 正则独立实验

承接用户“继续”及既定 P12 路线：先比较直接 UTF-8 路径与实际 Qt matcher，收益和兼容性不足时保留现状。用户不要求追加 Windows 复测；本地 master 中文提交，不推送。

## 方案

新增独立 CMake 工具，显式指定本机 Qt 配套 PCRE2 10.47 源码目录，使用其原有配置另编 8-bit 静态库。Qt 内部的 16-bit 库不是公开可复用 8-bit API；系统 10.46 不混入本次同版本对照。无自动下载，不复制 vendor，不影响顶层应用或 CI 依赖。

候选使用 PCRE2_UTF／UCP／NO_AUTO_CAPTURE 和原有大小写选项，保留真实 Qt 模式对象作语法校验和回退；只扫描有效 UTF-8、非行首 BOM 的行。坏编码／BOM 整行回 Qt，8-bit 不支持或依赖代码单元的模式（如 \C）逐模式回 Qt，运行错误也回 Qt。Qt 仍负责显示／高亮，实验额外验证首个完整匹配的字节位置转 UTF-16，不能声称全局高亮迭代已替换。

每个 matcher 自有 PCRE 编译结果、match data 和 JIT stack，无全局缓存；可移动不可复制，不允许同一实例并发调用。申请 JIT 并记录实际 JIT 程序数／代码字节；失败可用解释器，报告不能混称全部 JIT。所有权使用 RAII。

## 范围和取舍

先做独立组件，不接入 worker/UI。复用 Android 模拟语料及固定的单正则／多规则／大小写场景，补齐环视、命名反向引用、Unicode、空匹配、锚点、CRLF、NUL、坏字节、BOM、无尾换行、长行边界契约。比较完整命中位图，单独记录 matcher 构造、首次扫描和热扫描，冷热编译发生时机不同需同时报告构造加首次扫描总和。

原有默认 Qt 是主参考；Qt/Qt 控制观察波动。固定规则另用 Python 独立结果校验；复杂语法用人工固定结果与真实 Qt 对照。性能范围只覆盖内存中的逐行组件，不能外推为完整应用收益或全部正则语义等价。

不选择 Rust regex 统一替换，因为既有环视与反向引用需求会扩大回退边界；不调用 Qt 私有 PCRE 符号以避免 ABI 依赖。本轮不更改生产源码和默认配置，也不替换现有高亮／加速后端。
