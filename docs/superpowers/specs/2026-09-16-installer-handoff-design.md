# 安装版更新 3B：发布身份与安全交接设计

## 1. 已确认的方向

继承 `2026-09-15-installer-only-update-design.md`：仅 Windows x64 安装版、全量 NSIS 包、用户主动更新、生产入口默认关闭。用户确认采用独立的 `ZzLoggUpdate.exe`，不依赖 Qt，不常驻；不复用主程序的特殊启动模式，也不让提权后的安装器负责启动普通权限 GUI。

3B 分为四个可单独验收的子阶段，每个阶段提供自己的可执行计划。本文是整体设计，不将第一阶段完成描述成整个交接已实现。

## 2. 3B.1 构建发布身份（首个交付）

显示版本继续使用现有 `YY.MM.PP`。发布序号与显示版本独立，由发布流水线显式提供，不从 Git 提交数、当前日期、安装标记或注册表猜测。

CMake 增加 `ZZLOGG_OFFICIAL_RELEASE`（默认 OFF）、`ZZLOGG_RELEASE_SEQUENCE`、`ZZLOGG_RELEASE_CHANNEL`、`ZZLOGG_RELEASE_DATA_SCHEMA`。后三者默认空；正式构建要求全部明确提供。序号为 1 到 18446744073709551615 的规范十进制整数，与清单中的 uint64 字符串一致；数据 schema 为 0 到 4294967295 的规范十进制整数；渠道只接受 stable 或 preview。0 是可显式声明的数据 schema，不暗自把当前存储文件格式当成统一迁移版本。

身份版本来自 `ZZLOGG_DISPLAY_VERSION`，要求恰好两位数字的三个分量，月份 01–12，不支持额外非零构建号（Windows 数值资源第四段为 0 不影响显示）。同时检查 PROJECT_VERSION_TWEAK，避免其被显示版本归一化隐藏。正式构建只支持 Windows x64；同时检查编译目标架构与位宽，不能把 ARM64 当成 x64。开发构建即使残留正式字段也不产生正式身份。

生成头文件只包含经过验证的数值和受限字符串，挂接在无 Qt 的 `zzlogg_update_core`。身份读取返回 optional；身份是可比较的发布元数据，不是签名证明，也不授予启动安装器的权限。

Qt 适配层的纯函数结合发布身份、3A 的 InstallationIdentity 以及调用方提供的操作系统版本生成 InstalledRelease。只有 Registered 且根目录非空、正式元数据有效、目标 windows/x64、操作系统主版本非零时才返回 Installer 身份，其余返回空。不从用户配置或数据目录判断安装类型。

本子阶段不接线 `KloggApp` 的空发布身份，不改下载或 UI 行为，不探测操作系统版本，不创建更新程序，不运行安装器。后续接线须同时接入真实操作系统版本和上线门禁，不能拿测试版本代替。

## 3. 3B.2 执行前验证

保留可信清单的原始签名信封及选择上下文，执行时重新验证签名、时效、当前渠道、反回放状态和目标发布；不把 `DownloadSnapshot::verifiedPath` 当作执行授权。

对安装包重新核对大小和 SHA-256，并校验 Authenticode 信任及编译内置的发布者策略。缺证书策略、签名无效或状态无法确定时拒绝执行。验证至启动期间保持文件和路径稳定；只有经过 Windows 文件共享与路径替换测试的实现才允许进入启动阶段。

普通权限验证不能替代管理员阶段的独立验证。用户可写缓存及交接消息均不是管理员信任根。生产证书、服务端配置与真实 UAC 验收不具备时，测试替身只进入测试目标，禁止通过命令行开启生产后门。

## 4. 3B.3 独立交接进程

`ZzLoggUpdate.exe` 使用 C++17、Windows 系统 API、静态 CRT，不依赖 Qt 或安装目录的第三方 DLL。只在显式更新时运行，以原用户普通权限协调；若原进程已经提权，不承诺自动降权重启，改为提示手动启动。

协调者本身也属于受管理文件，不能从原安装位置长时间运行并期待安装器覆盖自己。交接阶段须实现经过验证的事务专属运行副本及安全启动路径，并验收其依赖仅为系统组件；该副本不作为提权代码信任来源。

本地通道使用访问控制、单次随机令牌、事务 ID、进程句柄及创建时间等真实进程身份。拒绝远程客户端、重放、超长消息、错误顺序与身份不匹配。令牌不进入普通日志。

主程序和协调者保持存活，直到安装器确认进入“等待应用退出”阶段。协调者启动安装器后不能仅凭启动 API 返回成功就允许应用退出。取消 UAC、启动失败、握手超时均恢复应用可操作状态；安装器握手前不得修改安装目录。

同安装目录更新锁覆盖所有实例与新启动入口，不能只依赖当前按应用标识工作的单实例通信。其他安装目录不受影响；无法协调的旧实例、其他用户实例或被占用文件应报告阻塞，不按进程名强杀。

## 5. 3B.4 保存、退出和界面接线

拆开当前 `closeAllWindowsForApplicationExit()` 的准备与关闭阶段。保存并同步所有会话成功后，窗口仍保持存在；等待期间限制会使保存快照失效的操作，取消则恢复。握手成功后提交退出，协调者等待真实进程退出，不能把窗口关闭当作进程结束。

界面只展示具备完整执行条件的“退出并更新”。便携副本只提示手动更新。仅测试进程链路验收不开放正式安装按钮。

协调者由原普通用户身份重启新版，保留经过限制的数据定位参数。安装完成不等于启动健康；3C 完成前不写入真实安装目录，不声称具备事务回滚。

## 6. 验收与边界

- 3B.1：真实 CMake 配置/生成测试、编译元数据读取、身份组合矩阵；默认构建仍无正式身份。
- 3B.2：篡改、过期、重放、渠道切换、发布者不匹配、文件/路径替换；全部在隔离临时目录。
- 3B.3：测试子进程覆盖握手成功、拒绝、超时、退出、重放、启动门禁和自身文件占用，不操作真实安装。
- 3B.4：会话保存失败、用户取消、多窗口、多实例、拒绝 UAC 时窗口仍可用；英文/简体/繁体与 150% 缩放。

3C 的受保护文件与登记事务、系统隔离环境中的真实 NSIS/UAC 验收及生产证书配置仍是正式开放更新的前置条件。
