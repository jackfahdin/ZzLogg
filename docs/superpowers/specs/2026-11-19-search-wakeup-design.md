# 后台搜索容量通知实验

目标是减少现有 worker 队列满时固定等待 1 ms 的延迟，同时保留结果、取消、更新和队列容量语义，不增加生产依赖。沿用用户已确认的优化顺序和自主实施授权。

## 实现方案

缩短轮询或忙等会增加 CPU 风险；直接重写 TBB 输入图影响范围较大。本轮采用标准库 condition_variable：生产者在同一 mutex 下检查 limiter 并进入等待；结果处理完成后，在同一 mutex 下递减 limiter，再通知。消除检查与入睡之间的丢失唤醒。超时仍为 1 ms，用于没有完成通知时检查取消，不把超时缩短当收益。

仅在 ZZLOGG_EXPERIMENTAL_SEARCH 副本中启用，运行时明确选择 `wake`；匹配保持真实 Qt，不混入 PCRE／memchr 收益。默认生产仍使用原轮询。保留最多线程数 × 3 个在途块及一个已读取待提交块；不中断单次匹配／转码，不改变结果合并或高亮。

## 验证与取舍

固定契约覆盖通知早于等待、阻塞后通知、取消且无释放、并发容量有界及实际 worker 全量／取消／追加更新。正式四轮 Qt+通知 对照 Qt+轮询与 Qt 同实现控制，使用已有合成 Android 正则语料及独立结果 oracle；测完整 wall time、进程 CPU time、首次通知、取消、等待／超时计数。进程 CPU 包括参与任务的线程和进程背景活动，不是系统 CPU 百分比。

只在完整结果、生命周期、实际路由和取消通过后报告性能；以测试证据决定是否值得后续生产采用。本轮完成可复现实验与明确结论，生产切换仍需单独评估同步复杂度和更多负载。
