# 运行时语言刷新与行号选项合并设计

## 目标

修复 ZzLogg 在运行时切换语言后，部分已经显示的菜单、设置项和日志搜索控件仍保留旧语言、必须重启才刷新的问题。语言切换应立即作用于当前所有窗口和已打开文档，并且不再被错误地归类为“需要重启”的设置。

同时把“主视图行号”和“过滤视图行号”合并为一个“显示行号”选项，由同一个配置值控制两种视图，并为已有用户提供确定、无信息丢失的配置迁移。

## 根因

应用翻译器本身可以在运行时正确安装，主窗口也已经响应 `QEvent::LanguageChange` 并刷新了大部分菜单和动作。残留问题来自下列未闭合的运行时刷新路径：

- 设置窗口只调用 Designer 生成的 `retranslateUi()`；构造阶段手工添加的存储标签、主题和正则下拉项、编码项、快捷键表等不在其覆盖范围内。
- 快捷键动作名称以已经翻译的字符串保存在函数级静态容器中。容器第一次初始化后，后续即使重建表格也只能得到旧语言。
- 存储位置页面和已打开文档的搜索区域在构造时设置文字，但没有完整处理 `LanguageChange`。
- 主窗口的最近文件子菜单、编码菜单、托盘动作、草稿板标题以及当前状态文字没有包含在现有重译函数中。
- 设置保存逻辑把“语言发生变化”并入通用的重启提示标志；重启重新构造所有控件后恰好刷新了文字，从而掩盖了上述问题。

两个行号选项则从菜单、动作、配置接口、内存字段到持久化键全部独立。它们的历史默认值也不同：主视图默认关闭，过滤视图默认开启。直接删除其中一项会丢失用户意图，必须显式迁移。

## 运行时语言刷新方案

采用“组件拥有自身文本，统一响应语言变化”的方案。每个持有构造期文本的长期存活组件提供集中重译函数，并在 `QEvent::LanguageChange` 到达时调用；主窗口继续作为顶层刷新入口，但不直接拼装子组件内部文字。

### 设置窗口

设置窗口的重译顺序为：

1. 调用 Designer 生成的 `retranslateUi()` 刷新静态控件。
2. 恢复带产品名的窗口标题。
3. 刷新运行时添加的 Storage 标签、Light/Dark、正则类型、正则引擎和 Auto 编码项。
4. 刷新快捷键表头和动作名称。
5. 通知存储位置页面刷新自身文字。

更新组合框文字时保留稳定的 item data、当前选项和用户正在编辑的其他设置。快捷键表不能通过无条件清空重建来刷新，因为这会丢失尚未点击“应用”的快捷键修改；应根据稳定 action key 原位更新名称和表头。

快捷键定义中的稳定 action key 和默认按键继续使用静态数据，显示名称改为未翻译的源文本或可延迟翻译的数据，每次展示时按当前语言求值。构造期裸字符串改为可提取的 `tr()` 文本，并补齐简体中文、繁体中文翻译。

语言变化不再设置通用重启提示标志。旧样式系统或存储位置变化原本需要的重启语义保持不变。

### 存储位置页面

存储位置页面保存说明标签和表单标签等需要重译的控件指针，并集中刷新：说明文字、三种存储模式、路径占位符、浏览按钮、打开目录按钮及数据目录标签。刷新后重新计算当前验证消息，使动态错误也使用新语言；路径、选择模式和有效性状态不得改变。

### 已打开文档与主窗口

`CrawlerWidget` 在现有 `changeEvent()` 中增加语言变化分支，刷新：

- 过滤可见性三项；
- 区分大小写、正则、反向匹配、逻辑组合、自动刷新等 tooltip；
- 搜索历史上下文菜单；
- 清除、搜索、保留结果按钮及其提示；
- 当前搜索结果或文件状态提示。

为需要后续更新的上下文菜单动作保留成员指针。预定义过滤器组合框提供自己的重译入口。

`MainWindow::reTranslateUI()` 补齐最近文件子菜单、编码菜单、托盘动作、草稿板标题以及当前窗口标题和可重建的状态文字。需要更新的菜单和托盘动作改为成员或交由对应组件提供重译函数。重新翻译只改变显示文本，不改变已打开文件、当前选区、搜索状态、菜单勾选状态或快捷键。

Quick Find 中现存的裸英文控件文字纳入翻译并响应语言变化；运行时产生的对话框和通知继续在显示时调用 `tr()`，天然使用当前语言。

## 行号选项合并方案

用户界面只保留一个可勾选动作 `Line &numbers`，中文显示为“显示行号(&N)”和“顯示行號(&N)”。动作位于 View 菜单原来两个行号动作的位置，由单一槽保存配置并发出 `optionsChanged()`。

配置模型收敛为：

- 单一 getter/setter：`lineNumbersVisible()` / `setLineNumbersVisible(bool)`；
- 单一内存字段；
- 单一持久化键：`view.lineNumbersVisible`；
- 新安装默认值为开启。

`CrawlerWidget::applyConfiguration()` 把同一个值同时应用到主视图和所有过滤视图。过滤视图仍显示匹配行在原始日志中的行号，主视图仍显示自身行号；本次只统一可见性，不改变数字语义和绘制方式。

## 旧配置迁移

读取配置时，新键优先。如果新键不存在，则检查旧键 `view.lineNumbersVisibleInMain` 和 `view.lineNumbersVisibleInFiltered`：

- 两个旧键都存在：新值为二者逻辑或；
- 只有一个旧键存在：直接采用该键的显式值；
- 两个旧键都不存在：采用新的默认值 `true`。

这样任何原本显示行号的视图在升级后都不会突然丢失行号。典型旧默认组合 `false/true` 会迁移为统一开启，因此主视图在升级后也会显示行号，这是合并两种行为后有意接受的变化。

迁移结果写入新键并移除两个旧键，避免后续继续维护两套语义。降级到旧版本时无法恢复原来两个视图各自不同的选择，这属于本次配置模型收敛的已知兼容性取舍。

## 错误处理与边界

- 若应用翻译资源加载失败，保持当前语言和现有错误返回，不保存一个无法安装的语言状态。
- 重译过程不得重建业务对象，不触发搜索，不改写文件，也不清空未保存的设置编辑内容。
- 本次覆盖现有简体中文、繁体中文和英文资源，不引入新的语言或翻译框架。
- 不改变行号的字体、颜色、宽度计算或过滤视图的原始行号语义。

## 验证

- 扩展应用翻译测试：先用英文构造存活的主窗口、设置窗口和文档搜索区，再依次切换简体中文、繁体中文并处理事件，断言动态控件立即更新。
- 覆盖设置窗口的 Storage 标签与页面、主题和正则下拉项、Auto 编码项、快捷键表头及至少一个快捷键名称；验证当前选择和未保存快捷键内容不变。
- 覆盖主窗口的正常菜单路径和此前遗漏的 Recent、Encoding、托盘、草稿板及当前标题；覆盖 CrawlerWidget 的过滤项、按钮、tooltip 和上下文菜单。
- 验证仅改变语言不会显示重启提示，也不会请求重启；原有样式和存储位置重启测试继续通过。
- 增加配置测试，覆盖新键读写、新键优先、两个旧键四种组合、单个旧键存在、完全缺失及旧键清理。
- 增加 UI 测试，验证 View 菜单只有一个行号动作，点击后主视图和过滤视图同步更新，并在新文档和切换标签后保持一致。
- 完成后运行相关定向测试、完整构建及全量 CTest。
