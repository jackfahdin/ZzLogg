# 搜索容量通知生产接入

## 目标与边界

沿用用户持续推进优化、保留功能和降低维护复杂度的授权。把已验证的通知方案收敛为生产和实验共用的一份实现，减少队列满时固定 sleep 的延迟。单执行名额和图异常收尾准入问题已解决，默认回归也已补齐。本轮完成接入、完整回归和最终代码的直接对照，再决定是否采用；不新增第三方库，不替换 Qt，不追加已取消的 Windows 验证。

## 实现方案

作者选择复用现有 condition_variable 门：移入 utils 的 `searchcapacitygate.h`，实验旧头只保留类型别名。它只有标准库依赖，保留同 mutex 下的容量检查／递减和代数变化通知，1 ms 超时检查取消。保留原统计计数，避免为去掉两个轻量计数器再引入模板或宏分叉。缩短轮询容易增加 CPU，重写整个 TBB 输入图影响过大，均不采用。

生产使用通知，原轮询只保留在显式实验副本作参考。每个结果回调离开时 scope guard 递减 limiter 后通知，包含取消早退；不再重复连接 decrementer。图上下文异常取消／排空机制原样保留，gate 在图之前构造，销毁顺序覆盖全部回调。单执行名额仍由生产者执行有界图任务，不阻塞在 gate 等待。

队列容量仍为匹配线程数 × 3 加生产者的一个待提交块。查询、布尔逻辑、转码、高亮、缓存及追加更新语义不改；单次正则／转码仍不可抢占。本轮不加 UI／持久化调度开关，回退使用独立 Git 提交。

## 验收与采用条件

将通知门的拒绝后释放、提前释放、无通知取消和 4096 次有界提交契约纳入默认 CTest。默认生产 worker 在全局 1／2 名额下复用搜索、取消和查询切换，独立 arena(1) 继续覆盖直接取消。显式故障矩阵、全量匹配、尾行更新及真实 Vectorscan 路由验证两种调度。

最终代码在固定 Android 模拟语料上运行四轮 ABBA／BAAB + Qt 控制，用独立 oracle 检查完整结果和路由，分别报告 wall／process CPU。性能阈值不进 CI。只有正确性和生命周期通过、主要受轮询影响的场景仍有收益且没有可确认的新普遍退化时保留生产默认；否则恢复默认轮询并记录原因。不宣称未验证的平台性能或严格实时取消上界。

## 评估后收敛

首次最终代码评估发现双线程布尔查询四轮都慢于轮询（汇总 wall 增加约 7.8%，CPU 增加约 10.8%）。作者决定回撤默认启用的生产 diff，不保留新开关或按查询类别硬编码选路；单一模式的收益不足以满足本项目不强行替换的约束。保留 utils 共用门、修正后的默认通知契约和双执行名额 worker 回归，最终代码再运行对照并归档全部数据。原 1 ms 轮询仍为生产默认。
