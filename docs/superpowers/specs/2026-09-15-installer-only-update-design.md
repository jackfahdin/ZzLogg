# ZzLogg 仅安装版在线更新设计

## 1. 决策与适用范围

用户已确认：仅 Windows x64 安装版提供在线更新；便携版继续发布并由用户手动更新。只使用全量 NSIS 安装包，不开发便携更新助手、ZIP 自动替换、差分更新、后台强制安装或常驻服务。

本设计取代《应用更新系统设计》中关于双分发类型自动安装、便携事务及其实现顺序的要求。已经完成的协议、签名验证、检查和下载能力保留；协议中的 portable 载荷类型不在本次删除，也不据此向便携版提供安装按钮。

本文件是设计，不表示安装执行或生产在线更新已经启用。当前基线为 master 的 82f3a1e3。

## 2. 已核实的工程现状

- `src/update`、`src/updateqt` 已完成可信清单与下载校验；`src/app/kloggapp.h` 仍以空发布身份创建服务。
- `packaging/windows/ZzLogg.nsi` 申请管理员权限、安装到 Program Files，并写入卸载项的 InstallLocation。
- 该脚本的 InstallDirRegKey 却读取另一个未写入的 Software\ZzLogg 默认值；必须统一读取和写入位置及注册表视图。
- `.zzlogg-install-root` 目前只是可读版本文本，不能单独证明安装身份，更不能作为提权授权。
- 当前安装段直接复制文件，没有事务日志、故障恢复或同目录多实例协调。
- 卸载段会删除部分历史用户配置；升级禁止调用卸载程序。
- 数据目录由用户选择，与是否安装版无关。安装位置和数据位置不得相互推断。

## 3. 组件与权限边界

| 组件 | 职责 | 边界 |
| --- | --- | --- |
| 安装身份探测 | 读取安装登记、标记和当前程序路径，给出一致性结果 | 只读；结果不是管理员授权 |
| 更新检查与下载 | 复用已实现的签名、选择、下载和缓存验证 | 普通权限；不修改安装目录 |
| 普通权限交接组件 | 保存会话、启动安装器、协调退出和普通用户重启 | 不加载目标目录中即将被替换的 DLL；不得冒用提权账号的数据目录 |
| NSIS 升级入口及事务组件 | 独立检查权限、目标、受管理文件与事务，执行和恢复 | 仅操作核实的原安装目录及受保护暂存/备份 |
| 发布流水线 | 固定发布身份、生成可信文件集、签名和发布 | 缺生产配置或验收时禁止发布可自动安装版本 |

不开发便携助手，但安装版仍需要可靠的普通权限交接能力；是否以主程序的专用受限模式或单独小程序承载，在交接阶段以依赖和生命周期测试作出选择，不混入本期身份探测实现。

## 4. 安装身份与引导版本

安装登记以 `HKLM\Software\Microsoft\Windows\CurrentVersion\Uninstall\ZzLogg` 为唯一来源，Windows x64 使用 64 位注册表视图，读取 InstallLocation。写入、卸载清理和探测采用同一视图。

当前程序必须位于已登记目录；路径大小写按 Windows 语义处理，但不能通过跟随重解析点把任意目录变成可信目录。检查目录及祖先、主程序和标记，遇到重解析点、读取失败或路径不一致时拒绝自动安装。

引导版本增加 DWORD `UpdateIdentitySchema=1`。登记项、原安装标记和程序路径一致，只说明可进一步核对该安装；发布版本、发布序号、架构和渠道仍来自构建内置身份，受管理文件集合必须来自受信发布产物，而不是扫描用户目录生成。

缺少登记、复制出来的目录、旧版本仅有历史标记、非 Windows x64 或开发构建均不得启用自动安装。旧安装需手动安装一次引导版本；不能通过猜测旧文件列表删除文件。一个正常便携副本即使机器上另有安装版，也不得更新那个安装目录。

## 5. 用户流程与退出交接

1. 用户检查更新，查看说明并主动下载；便携版只提示手动下载，不下载并执行安装版载荷。
2. 安装版的全量包验证完成后显示“退出并更新”和“稍后”。执行能力没有完成验收时，不显示可用的安装操作。
3. 用户确认后先完成会话保存及同目录实例的退出准备；用户取消保存时不启动安装器、不退出。
4. 执行前重新检查签名、有效期、发布选择及完整包大小/哈希，并验证安装器代码签名和预期发布者。不得把缓存存在或界面的 Verified 状态当作长期执行授权。
5. 启动安装器并确认受限交接成功后再允许主程序退出。用户拒绝 UAC、进程启动失败、握手失败或超时，均保持原应用可用；安装器不能提前写入目标。
6. 以真实进程身份和同目录更新锁等待全部相关实例正常退出，阻止新实例在替换期间进入。不按进程名强杀，也不影响其他目录的实例。
7. 安装完成后由普通用户协调者启动新版，保留必要的数据定位参数。另一管理员凭据不得改变原用户身份；协调者丢失时提示原用户手动启动，禁止用管理员身份直接启动 GUI。

握手使用带访问控制的本地通道、单次随机令牌、事务 ID 和进程校验；令牌不写普通日志。启动成功不等于安装成功，安装成功也不等于新版启动健康。

## 6. 提权与受保护事务

高权限代码不能信任客户端传入的目标路径、文件列表或“已校验”标记。安装器独立核对登记、发布身份、原安装路径及文件系统边界；所有路径检查还必须覆盖实际文件操作，防止检查后替换。

可执行安装器在普通权限启动前完成验签/验包与代码签名校验，并保证校验到启动期间的文件稳定性。管理员阶段在受保护位置暂存和验证载荷，不从用户可写目录加载高权限 DLL 或执行用户提供的恢复脚本。

事务顺序：准备 → 备份 → 应用文件与登记 → 等待启动确认 → 完成；失败进入恢复，无法安全恢复则保留备份并报告人工恢复要求。

- 原目录升级，不先卸载。新装向导仍允许选择目录，专用升级入口不允许切换目标或重新选择关联/快捷方式。
- 新旧可信文件清单决定改动集合；未知文件不删除，已修改受管理文件或用户数据与新载荷冲突时停止。
- 保护用户配置、收藏、会话、存储定位文件及所有已知数据根；不得递归清空安装目录。
- 目标所在卷预留暂存、备份和日志空间；每次操作前持久化可恢复记录，使用幂等恢复，不把多个文件移动声称为整体原子操作。
- 安装版本、卸载清单和登记属于同一事务，记录旧值并可恢复。保留原关联和快捷方式选择。
- 普通失败自动恢复本次改动；进程或系统中断后，下一次恢复需要明确 UAC 授权。禁止承诺断电时也能无提示回滚。
- 启动确认前保留备份，禁止不可逆数据迁移。新程序仍运行时不得盲目覆盖回退；数据不做整目录回滚。

## 7. 发布与上线门禁

在线清单只向安装版选择 `installer/nsis-exe`。便携发布产物可继续存在，不进入自动执行路径。清单解析器保留 portable 的兼容语义，避免无关协议变更。

生产 HTTPS、允许主机、清单公钥、代码签名证书及发布者策略、正式发布序号和构建身份缺失时关闭安装能力。不伪造生产配置，不使用仓库测试私钥发布，不在本机写真实 HKLM 或模拟系统级升级。

真实 Windows 隔离环境验收必须覆盖：旧版升级、Program Files、UAC 取消、另一管理员账号、同目录多实例、文件占用、空间不足、篡改/路径替换、进程终止、重启恢复、安装登记与用户数据保持，以及新版失败后的恢复。通过源码契约测试不等于通过真实安装测试。
