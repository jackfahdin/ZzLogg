# ZzLogg 应用更新系统设计

## 1. 范围与目标

首期支持 Windows x64，沿用 Qt 6 主程序与 ZzPureTools 静态链接方式。安装版和便携版共用程序及检查、下载界面；便携版使用独立更新助手，安装版使用 NSIS 专用升级流程。

首期仅全量包，不实现差分、强制更新、常驻服务或跨平台文件替换。已有其他平台的构建不能受影响；其更新入口明确显示该平台尚不支持自动安装。

安全目标：更新失败不破坏可运行的旧程序，不删除用户数据，不运行未经信任的载荷。无法确认目标、权限、兼容性或签名时终止安装，允许继续使用当前版本。

本文件是实现前设计。提交此文件不代表在线更新功能已实现或上线。

## 2. 当前工程事实

- `src/versioncheck` 仅查询版本并发送通知，缺少下载、安装和恢复能力。
- `cmake/ZzLoggBrand.cmake` 中更新清单地址为空。
- 现有检查失败后仍推迟七天，稳定渠道由版本列表间接推断，需替换这些规则。
- `packaging/windows/ZzLogg.nsi` 使用管理员权限、系统级注册表和安装目录；当前复制流程不具备事务性升级能力。
- 安装器的卸载流程涉及历史配置文件，升级不能通过先卸载旧版实现。
- `cmake/DeployPortable.cmake` 会清空构建产物目录，禁止作为用户端更新脚本执行。
- `StorageContext` 已将数据位置与发布类型分离。数据目录可以位于程序目录内部，也可以由 `--data-dir` 指定。

## 3. 模块边界

| 模块 | 职责 | 禁止事项 |
| --- | --- | --- |
| 更新服务 | 检查、选择版本、下载、验证、进度与用户选择 | 不直接修改正在运行的程序目录 |
| 清单验证核心 | 签名、版本、架构、路径、哈希与发行渠道规则 | 不依赖 GUI，不实现自创加密算法 |
| 便携更新助手 | 等待退出、独占目标、替换、事务恢复、启动 | 不依赖目标目录中的 Qt DLL，不接受任意命令脚本 |
| NSIS 升级入口 | 权限提升、程序更新及安装登记一致性 | 不执行卸载流程，不接收任意目标路径作为可信指令 |
| 发布流水线 | 生成文件集、签名、上传、最后发布清单 | 不把签名私钥写入仓库或发布包 |

检查和下载可使用现有 Qt 网络能力。助手及安装器共用无 GUI 的验证/事务规则，降低两套实现出现不同安全边界的风险。

## 4. 发布类型与升级路径

每个发布包包含部署描述，记录产品 ID、发布类型、架构、渠道、发布序号及受管理的文件列表。文件列表来自构建产物而不是扫描用户目录生成。

安装版还需验证安装标记、安装登记及规范化路径一致。标记仅用于识别，不构成提权授权。对复制过的安装目录或无法可靠判断的历史版本，只允许提示下载完整包，不自动选择另一个目录覆盖。

便携包更新不创建注册表和快捷方式。目标不可写时首期不自动提权，提示下载新版到可写位置。安装版保留原安装路径、安装范围及用户原来的关联/快捷方式选项；不重新启用用户取消的文件关联。

首次具有更新能力的版本是引导版本：当前已发布且没有更新能力的旧版本，需手动升级一次。缺失可信旧文件清单时不能猜测并删除旧文件。

## 5. 版本与渠道

- 显示版本保持 `26.09.00`；逐段数值解析，禁止字符串字典序比较。
- 另设单调递增的发布序号，稳定版、测试版明确标识，不根据是否出现在历史列表中推断渠道。
- 同一发布序号及版本对应的安装载荷不可被重新上传替换；更正发布产生新版本。
- 首期公开界面默认稳定版。切换渠道不能绕过发布序号、签名或数据格式兼容检查。
- 开发构建默认关闭自动安装，不假冒正式发布身份。
- 安全反降级判断与本次事务回退分开：只能恢复此次更新前已经验证的备份，不能以“回退”为由安装任意网络旧包。

## 6. 签名清单与托管契约

采用 HTTPS 静态清单和不可变的版本化下载地址，不要求业务服务器。实际域名、托管账号及生产公钥由维护者配置；缺少任一必需配置时发布门禁失败，开发构建只能使用隔离测试源。

清单使用签名封装：封装中携带原始负载字节的 Base64、签名及 key ID。先对原始字节验签，再解析负载，避免客户端与发布端 JSON 重排造成歧义。限制封装大小并拒绝重复关键字段及未知协议版本。

负载字段：协议版本、产品 ID、元数据序号、签发/过期时间、渠道、发布序号、显示版本、最低系统版本、最低更新协议版本、数据格式兼容范围、多语言更新说明，以及平台/架构/发布类型对应的载荷列表。

每个载荷记录 URL、字节长度、SHA-256 和包格式。包内文件清单覆盖相对路径、长度、哈希及合法文件类型，并受外层包哈希和清单签名约束。

签名使用成熟库提供的 Ed25519 实现，禁止手写密码算法。生产私钥离线或位于受控签名环境；测试私钥只用于测试，生产构建明确拒绝测试信任根。客户端内置生产公钥，不从未验证的清单动态信任新公钥。

密钥轮换使用已信任密钥签署的、有序且有期限的信任元数据；在轮换链实现并测试之前，首期更换信任根必须通过旧可信更新链发布新版客户端。签名私钥丢失或泄露时停止受影响渠道自动安装，不能用普通公告替代可信授权。

保存已见元数据序号，拒绝过期和回退清单。显著异常的系统时间产生明确错误，不关闭期限校验继续安装。允许本地普通用户完全篡改应用和信任状态不属于本更新器可独立防御的场景。

重定向不能降级 HTTP；最终下载主机受发布配置约束。企业代理采用系统信任配置，更新请求不能继承日志下载功能的“忽略 SSL 错误”选项。

## 7. 用户交互

入口为“帮助 → 检查更新”和“设置 → 更新”。默认每天后台检查一次，只通知、不自动下载、不强制关闭。失败采用有上限的退避重试；手动检查绕过周期限制但不启动并发重复请求。

更新窗口显示当前/新版本、更新说明、下载体积、安装类型和权限要求。操作包含下载、稍后提醒、跳过此版本；下载中可取消，失败可重试。

下载验证完成后提供“立即重启更新”和“稍后”。安装阶段开始后不提供会打断事务的取消按钮。用户取消会话保存或拒绝 UAC 时，旧程序仍可继续运行或重新启动。

安装前所有属于同一程序目录的实例必须正常保存并退出，不强杀。未保存草稿需要显式处理；仅保存会话列表不等于保存草稿内容。其他目录的 ZzLogg 实例不受影响。

新旧应用和助手通过受限本地通道协调，使用事务 ID、随机令牌及进程身份校验。随机令牌不写入普通日志，不以进程名匹配代替身份验证。

## 8. 下载与暂存

下载缓存置于当前用户专用缓存位置，而不是任意日志目录。网络超时、大小超限、长度/哈希不匹配或签名错误均终止流程。首期可取消并重新下载，不把断点续传作为发布前提。

载荷在独立暂存目录展开，不直接解压到正式目录。禁止绝对路径、`..`、盘符路径、备用数据流、设备名、重复或大小写碰撞路径，以及符号链接和重解析点；设置文件数量、单文件和展开总量上限。

下载空间和事务空间分开预检：缓存需要压缩包空间；目标所在卷需要新文件、旧文件备份和事务记录空间。磁盘不足在退出旧程序之前报告，执行中空间不足仍进入恢复路径。

## 9. 便携更新事务

状态：已验证 → 已准备 → 等待退出 → 应用中 → 待启动确认 → 已完成；应用中断或失败进入恢复中，恢复失败进入需人工恢复。

助手运行于目标目录以外，不加载即将替换的 DLL。对同一规范化目标路径使用更新锁，并阻止更新中启动新的同目录实例。旧版本尚不能配合启动锁时，不提供无人值守覆盖升级。

应用前重新验证包、文件清单、目标身份和受保护路径。按旧版可信文件清单与新版清单计算操作，不以整个目录清空实现替换。

每步先写可持久化事务记录，再备份/移动文件，完成后记录结果。备份和最终暂存使用目标所在卷；不把跨卷目录移动当作原子操作。整套多文件替换不声称天然原子，由日志和幂等恢复实现可恢复性。

删除只针对旧版受管理、新版已移除且未被用户修改的文件。已被修改的受管理文件、未知文件与新版路径发生冲突时停止并要求处理；不得擅自丢弃。

明确保护 `StorageContext` 的数据根、定位文件、命令行覆盖数据根、其他同目录实例的数据根，以及不属于应用载荷的内容。保护路径与新文件列表冲突时拒绝安装，而不是跳过文件继续得到不完整版本。历史自定义数据无法完整枚举时，受管理白名单仍是最终保护边界。

替换后以原普通用户身份启动应用，保留必要的存储参数。应用在初始化和兼容性检查完成后确认事务；确认前不得执行不可逆配置迁移。超时不直接覆盖仍运行的新程序，先确认它已退出；无法退出时保留备份并提示恢复。

失败恢复本次事务触及的程序文件。数据默认不回滚；发生兼容迁移时仅按专门迁移记录恢复相关配置，不能把整个用户数据目录覆盖成旧快照。

## 10. 安装版升级事务

下载和初次验证在普通权限下完成，用户确认后调用签名安装器的升级入口。安装器在提升权限之后独立验证载荷，不信任普通用户传入的“已校验”标志。

不能从用户可写暂存目录直接加载高权限执行依赖。安装器将载荷复制到受保护的暂存位置，再验签、验哈希并从受保护副本执行，防止验证之后被替换。

高权限目标必须同时通过安装登记、产品标记、文件清单和路径边界检查，拒绝重解析点及任意目录覆盖。备份与事务日志使用受保护位置，普通用户不能构造回退目标。

安装器执行同样的受管理文件事务，并将安装版本、卸载清单等登记作为事务的一部分；所有需要修改的登记值有明确旧值和恢复操作。不能把“NSIS 返回成功”作为应用启动成功的替代。

普通权限协调者负责重新启动 GUI。完成安装不能让主应用以管理员身份长期运行；UAC 使用另一管理员账号时也不能把该账号当成用户数据所有者。

安装失败由仍处于提升权限的安装器恢复。如果进程或系统中断，需要再次明确请求 UAC 执行恢复；不安装隐藏服务来绕过授权。人工恢复入口保留备份和事务说明，不能声称任何情况下都能无提示自动回退。

## 11. 发布与增量演进

同一次构建生成完整文件集、便携包和安装包。先完成代码签名，再计算最终包哈希，上传不可变载荷并验证可下载，最后签名和发布渠道清单。代码签名证书和清单签名密钥分开管理。

流水线必须验证：包内版本一致、生产信任配置存在、没有用户数据、只有目标架构文件、许可证完整、升级/恢复测试成功。发布地址切换需经已有可信渠道授权。

首期只全量。文件级增量可以在后续复用同一暂存和事务接口：验证旧文件哈希，复用不变文件，下载改变文件，最终组装并验证完整新版。二进制差分还需匹配旧文件和补丁基线；失败退回全量。不引入多级补丁链。

## 12. 验证与交付门禁

自动测试覆盖版本/渠道选择、过期/回退/错误签名、协议拒绝、HTTP 降级、坏包、越界解压、大小写碰撞、磁盘不足、权限错误、未知文件冲突、数据目录保护。

便携事务在每个文件操作边界注入失败，验证重启恢复、备份保留、多实例协调、用户取消、启动确认失败和新进程尚未退出的处理。

安装版在隔离 Windows 虚拟机验证 Program Files、普通用户、UAC 取消、另一管理员凭据、升级中断、恢复提权、卸载登记和文件关联保持。未完成这些测试之前安装版自动升级保持关闭，不能以便携测试替代。

UI 验证简体、繁体、英语，深浅色以及 150% 缩放；离线使用主程序不受更新故障影响。现有 64 项回归测试继续执行，但不能替代新增的更新安全和事务测试。

## 13. 实现分期及外部配置边界

1. 清单协议、版本规则、签名验证及测试发布工具。
2. 检查/下载/通知界面，使用隔离测试源，不启用生产自动安装。
3. 便携助手、数据保护与故障注入，完成端到端恢复测试。
4. NSIS 升级入口和受保护事务，完成管理员权限虚拟机测试。
5. 配置生产托管与公钥、验证引导版本，再开启真实更新渠道。

各期使用独立实现计划，按可测试交付物提交中文标题和详细中文说明。当前用户未提供生产域名、签名公钥及证书，开发不因此停滞，但上线必须等待维护者配置并确认。不会创建外部账号、付费服务或在用户机器上模拟真实系统级升级。
