# P11：纯文本与多关键词首轮对照

**基线：** `864b98c`。按既定路线做隔离实验，以现有 Qt 默认匹配器为语义基线，不直接将第三方库接入应用。

**方案取舍：** 先比较不新增依赖的 QString／标准库查找，再与 Rust memchr、aho-corasick 的批量接口比较。Rust 库只存在于显式实验构建，锁定版本与校验和；正常应用构建无需 Rust。StringZilla 及应用集成留作后续准入，避免同时引入所有候选。

## 结构与执行

- [x] `tools/benchmarks/literal_search/`：独立 CMake 工程，直接编译现有 `DefaultRegularExpressionMatcher` 头文件作为基线。共同接口按批次返回逐行、逐模式的完整位图；Qt 基线仍逐行调用现有生产接口。候选为 QString::contains、std::string_view::find、memchr::memmem::Finder 与 aho-corasick 全重叠匹配。
- [x] `contract.cpp`：确定性对照非 ASCII、忽略大小写、空关键词、重复／包含／重叠模式、NUL、异常 UTF-8、BOM、截断视图和无效 UTF-16 查询；不支持的查询整体回退 Qt，字节候选对异常 UTF-8／行首 BOM 回退。保留每个模式的结果顺序，不把“任一命中”代替整个位图。
- [x] `main.cpp` 与 `scripts/dev/benchmark_literal_search.py`：测量构造、首次扫描和预热扫描；覆盖 1／4／16／64 模式、短／长关键词、短／长行、不同命中率及编码。进程固定 CPU，候选与 Qt 采用 ABBA 顺序，多轮记录原始样本、输入／结果摘要及构建环境；额外测高重叠且存在未命中模式的压力场景。
- [x] 对照结果写入本记录，独立审查、项目回归及中文提交，不推送。

## 等价条件与测量边界

只有全部模式为非空、区分大小写、有效 UTF-16 的纯文本查询才进入候选路径。忽略大小写、正则、空关键词和无效 UTF-16 查询统一回退现有 Qt；不自行实现 Unicode 大小写折叠。字节候选逐行验证 UTF-8，并对行首 BOM 回退，计时包含验证、结果写入和 Rust 批量 FFI 适配。QString 候选复用 Qt 解码再查找。

默认 Qt 匹配器在首次 match 时编译／JIT，首次扫描单独记录，热扫描双方先预热。Rust 每批只跨一次 FFI，不能将结果直接外推到目前应用逐行调用的开销。Qt 基线每行构造生产 MatchedPatterns，候选使用批次位图；结果体现接口与算法共同变化，不是库单函数的纯对比。

匹配器输入是 RawLines::buildUtf8View 的输出；UTF-16／其他编码的转码、磁盘读取、取消、UI 和高亮偏移不包含在热扫描计时。高亮目前仍用 Qt，不能据通知位图等价宣称偏移／整应用集成完成。自动机结构内存可单独记录，不能当作进程峰值或完整分配成本。

## 采用条件

仅在重复测量有稳定收益、构造／首次结果／内存／回退成本可接受，且实际应用和平台验证通过后接入。本轮不能把单机实验或候选契约通过标记为整个 P11 完成。


## 首轮结果与决定

**保留生产实现，继续候选评估。** 不采用无条件的标准库或 aho-corasick 替换。memchr 在本轮合格输入中值得继续研究，但尚未证明其 Rust 工具链、批量接口和实际应用集成成本合适。下一步优先将 C/C++ StringZilla 接入同一基准，再决定有限范围的生产试验；本轮没有测量 StringZilla，不能推断它一定更好。

### 环境与方法

Linux x86_64、Intel Core i7-14700，固定允许集合中的 CPU 0，未锁频；Qt 6.11.1、GCC 15.2.0、Release `-O3 -DNDEBUG`、C++ LTO 关闭；rustc 1.100.0，Cargo release、memchr 2.8.3、aho-corasick 1.1.5。144 个常规场景加 3 个压力场景，每批 128 行，5 组配对（4 个候选＋同实现 Qt 控制），4 轮、11,760 条热扫描记录。每侧每场景 8 个热样本，构造及首批扫描各 4 次独立测量。

测量包含完整位图 checksum 遍历、输出分配、编码验证和 FFI 适配，不是纯查找内核耗时。UTF-8 场景关键词实际为 7／27 字节，ASCII 为 4／24 字节；名称中的 n4／n24 是基础长度。随机背景可能有额外自然命中，原始记录另含实际命中行／单元数。

同实现 Qt 控制的全部场景倍率范围约 0.666～1.385，说明本机小样本仍有明显噪声／布局影响。接近 1 的差异不能作为采用或候选排名的依据，不将跨场景中位数解释为整体应用提速。

### 代表场景

下表为各候选**相对其配对 Qt 基线**的热扫描中位数倍率；大于 1 表示更快，小于 1 表示更慢。各组的基线独立测量，不能把微小倍率差直接当作候选之间的排名。h50 指目标 50% 的行注入某个模式，并非每个模式都有 50% 命中率。

| 场景 | string_view::find | QString::contains | memchr | aho-corasick |
| --- | ---: | ---: | ---: | ---: |
| ASCII，128 字节，1 个短关键词，h50 | 8.31× | 1.89× | 10.53× | 6.91× |
| ASCII，4096 字节，64 个长关键词，无注入命中 | 5.63× | 5.33× | 41.84× | 162.15× |
| Unicode，4096 字节，16 个短关键词，h50 | 0.87× | 0.64× | 5.37× | 8.95× |
| 长公共前缀，4096 字节，1 个关键词，未命中 | 0.14× | 0.87× | 10.70× | 0.46× |
| 长公共前缀，4096 字节，64 个关键词，未命中 | 0.20× | 1.31× | 46.00× | 59.80× |
| 高重叠，4096 字节，64 模式中 1 个未命中 | 428.26× | 57.33× | 141.86× | 0.18× |

标准库在长公共前缀未命中时约慢 5～7 倍，因此不能直接作为统一快速路径。aho-corasick 为保留每个重叠模式的命中而枚举大量结果，在高重叠压力场景约慢 5.5 倍；换成非重叠 API 会改变结果，不能用这种方式“修复”性能数据。普通缺失／稀疏匹配下多模式一次扫描收益明显，但不适合据此全量替换。

memchr 在这批合格输入（常规有效 UTF-8＋压力场景）中的倍率最低约 1.63，最高约 141.86；只能说明本轮值得继续，不证明所有输入、平台或实际用户日志无退化。异常 UTF-8 下字节候选回退 Qt，其小幅时差受控制波动影响；QString 候选可以直接使用 Qt 解码后的替换文本。

### 构造、首批与成本

以 ASCII／4096 字节／64 个长关键词／未命中为例，以下是各候选配对实验的中位数，首批包含 128 行：

| 实现 | 构造 | 首批扫描 | 对应 Qt 构造／首批 |
| --- | ---: | ---: | ---: |
| std | 14.5 μs | 4.83 ms | 8.5 μs／31.45 ms |
| QString | 13.8 μs | 3.64 ms | 8.9 μs／21.26 ms |
| memchr | 21.4 μs | 0.71 ms | 9.0 μs／29.33 ms |
| aho-corasick | 270.3 μs | 0.19 ms | 9.2 μs／29.54 ms |

自动机构造更贵，较大批次仍可摊销；这不等于首次一行结果的延迟，也不是全新进程启动时间。aho-corasick 本轮最大报告自动机内存为 184,192 字节，未统计其外层 Qt 回退状态、模式存储、分配器开销或进程峰值。

独立可执行文件在本机默认链接下，C++ 版本为 288,944 字节，启用两种 Rust 候选为 6,050,488 字节；GNU size 的 text 段分别为 229,340／1,492,680 字节。该差异包含独立工具的链接与符号成本，不代表接入应用后的安装包增量。生产构建本轮没有增加 Rust 依赖。

### 验证与可复现材料

- 不启用 Rust 的独立 Release 构建成功，3 个后端通过边界及 1,024 条确定性随机输入对照。
- 显式启用 Rust 的 Release 构建成功，5 个后端通过同一契约；147 个计时场景的完整位图和跨轮输入／结果摘要一致。
- `cmake --build out/build/p6-boolean --target ci_build --parallel 12` 成功。
- `QT_QPA_PLATFORM=offscreen ctest --test-dir out/build/p6-boolean --output-on-failure --parallel 8`：97/97 通过。
- `python3 -m unittest discover -s tests/ci -p 'test_*.py'`：124 项，3 项跳过，无失败。
- 独立只读审查与复审未发现阻塞项；已修正实际长度标签、混合无效 UTF-16 契约、Qt 最低版本，并注明 checksum 成本。审查没有代跑性能负载。

最终原始数据在 `out/benchmarks/p11-literal/final/`，不提交构建产物；二进制 SHA-256 为 `3bff482a50d8f2b4c60739901bc4ce52f2b3c6d1994a2b1a9fec66e00671dbaa`。原始 JSONL、源码摘要、CMakeCache、CPU 和 Rust 版本均由 runner 保存。复现步骤、完整测量边界见 [实验 README](../../../tools/benchmarks/literal_search/README.md)。
