# 搜索 worker 复用回归实现计划

> **面向 AI 代理的工作者：** 使用 executing-plans 内联执行，最后做一次独立审查。

**目标：** 补齐默认生产测试的同 worker 取消后重搜和单槽 arena 生命周期覆盖。

**架构：** 直接链接生产库，保留真实临时文件、索引、Qt 事件循环和 TBB。异步 worker 的取消可能与完成竞争，接受有效的部分或完整结果；同步 arena 在首次中间进度直接设置取消标志，必须得到非空部分结果，再复用相同 operation/data 完整重搜。

**技术栈：** C++、Qt Test、oneTBB、CTest。

**规格：** [上一轮恢复修复的待办](2026-11-19-search-worker-recovery.md)。本计划只扩展测试，不改变生产行为。

## 全局约束

不新增依赖或生产测试钩子。保留 Qt 和默认轮询；不追加 Windows 验证。沿用已授权的本地 master 开发和中文提交，不推送。

## 审查重点（Review Focus）

- 很快的异步搜索允许取消晚于实际完成，但仍须检查取消已请求和后续搜索重置标志。
- 同 worker 更换查询后，不残留前次位图、宽度、计数或已消费增量。
- 每轮终态和完成各一次，终态先于完成；arena 直接回调不跨线程共享非原子状态。
- 单槽 arena 单独生效时也有取消和重搜，不能仅依赖 global_control(1)。
- 停滞仍由 CTest 30 秒硬超时兜底，不以长日志或 sleep 制造取消窗口。

## 实现与验证（2026-11-20）

默认测试现在对 1／2 个匹配节点分别复用同一个生产 worker。取消请求经原 Qt 进度转发到达，允许任务已经完成；后续查询从 ERROR 切换为 ok 再切回 ERROR，严格核对行号、4096 命中、宽度 11／2，以及消费后增量为空。每轮终态和完成必须各一次且顺序正确。

单槽 arena 的全局上限显式设为 2，独立覆盖 arena 限制；直接进度回调在首个中间进度设置取消标志。部分搜索必须非空且不完整，同 operation/data 清除取消标志后完整重搜，累计计数不得保留前轮数据。处理范围是最大已处理行号，不把它独自视为所有前序行都已完成的证据。

两项临时生产变异证明测试敏感性，随后恢复源码：

- 删除 worker 搜索前的取消标志清除：重搜以 `Complete result lost rows` 失败，退出码 1。
- 删除 arena 单执行名额识别：单槽 arena 停滞，由独立 8 秒限时捕获，退出码 124。

恢复后默认 `ci_build`、离屏 CTest **98/98**、Python CI **141 项（3 项跳过）**全部通过。CPU 0 亲和性运行通过，目标 CTest 连续 **20 次**通过；`git diff --check` 通过，生产源码无 diff。本轮仅测试和文档变更，不重跑性能基准，也不新增性能或跨平台结论。

验证日志归档到 `out/benchmarks/p12-worker-reuse/validation/`。后续再收敛容量通知的生产实现和兼容性验证，Qt／原多 CPU 轮询继续作为默认。
