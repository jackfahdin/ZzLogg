# P6：布尔求值器兼容迁移

**基线：** `54407c3`。按已确认路线推进；不以删除依赖为强制目标。

**目标：** 保持当前逻辑搜索的有效语法、优先级、结合性、匹配结果和反选行为，收回有限布尔语法的求值，移除 ExprTk 与仅为其服务的 robin-hood。

**方案：** 先用当前实现生成固定真值表与错误样例。新实现使用有界递归下降解析器生成后缀指令，查询创建时分配执行栈；四个及以下变量仍使用 16 项真值表，较大表达式每行只读命中值、执行指令，不动态分配。保留 `BooleanExpressionEvaluator` 调用接口和前置引号提取。相比跨语言引擎，不增加运行依赖；相比保留 ExprTk，只保留项目实际接受的布尔语法。实际操作符含义以旧实现对照为准。

## 兼容性发现

旧 ExprTk 的泛用数学能力不属于公开搜索语法；前置白名单早已排除数字常量、算术和语句。此次保留前置引号提取、转义、大小写处理、反选和模式匹配方式。实际语法如下：

| 优先级（高到低） | 语法 | 行为 |
|---|---|---|
| 分组／单目 | `(expr)`、`not(expr)` | `not` 必须带括号 |
| 隐式乘法 | `p_0 p_1`、`p_0(p_1)`、`(p_0)(p_1)` | 对 0/1 命中值等价于 AND |
| 与组 | `and`、`nand`、`&` | 同级左结合 |
| 或组 | `or`、`nor`、`xor`、`xnor`、`|` | 同级左结合 |

`&`／`|` 保留布尔求值短路；它们不跳过此前的正则匹配。`!` 虽在原前置白名单里，却一直不能被旧求值器正确编译；`!`、`&&`、`||` 继续拒绝。原测试曾对无效的 `!` 查询仅检查结果为 false，现已改为有效的 `not(...)` 并断言查询有效。

旧 vendor ExprTk 被裁剪过，部分复合 `nand/nor/xor/xnor` 表达式会因缺少通用操作映射报 ERR015。新实现修复这些组合：410 条原始探针对照中，98 条原来无效的表达式现在可正确求值；3 条原始算术写法不再接受，但这些写法从未通过公开搜索入口。240 条旧实现接受的公开语法用例完整真值表均保留。直接求值器支持制表符、换行等空白，公开前置语法依然拒绝它们；fixture 已区分这两层。

新增边界是有意的行为变化：公开布尔输入最多 65536 个 UTF-16 代码单元，规范化求值器输入最多 65536 字节，最多 4096 个子模式、256 层括号。长输入包含模式文本；模式替换为 ID 后还会再次检查长度。错误从 ExprTk 内部错误码改为明确说明及零起始位置；解析错误位置仍指规范化表达式，不承诺对应原输入列号或保持旧诊断措辞。

## 实现与清理

有限递归下降编译为指令，`&`／`|` 使用前向条件跳转。四变量以内预计算真值表；较大表达式使用预分配栈。二元指令合并直接右侧变量读取，减少逐行解释分派，栈容量保持保守上界。每个匹配器独立持有状态，不引入跨线程共享。

删除 ExprTk 和 robin-hood 的 166 个 vendor 跟踪文件，共 7565866 字节（约 7.22 MiB），同时删除失效 Find 模块、目标及链接、残余 include 和 NOTICE 项。此数字是源码清理量，不代表可执行文件或内存缩减量。历史文章中的库名保留。

## 性能记录（2026-11-14）

Linux／GCC Release／Qt 6.11.1，旧基线 `54407c3`；相同探针在变更前后分别链接真实实现。8 轮交替进程顺序，每版 16 个计时样本。下表为中位数，单位 ns；构造包含析构。

| 模式数／操作 | 创建旧 → 新 | 热求值旧 → 新 |
|---|---:|---:|
| 1／and | 35192 → 177 | 1.96 → 1.91 |
| 4／and | 32425 → 310 | 2.46 → 2.07 |
| 6／and | 36353 → 316 | 9.35 → 8.47 |
| 6／& | 33168 → 315 | 10.36 → 8.87 |
| 16／and | 44053 → 1422 | 26.50 → 26.81 |
| 16／or | 44826 → 1407 | 26.83 → 23.34 |
| 16／&#124; | 40545 → 1268 | 28.26 → 28.13 |
| 64／and | 80063 → 5000 | 153.66 → 83.15 |
| 64／or | 79483 → 4852 | 162.34 → 93.92 |
| 64／& | 68029 → 4765 | 149.35 → 116.52 |
| 64／&#124; | 67386 → 4762 | 153.00 → 118.87 |

创建成本明显降低；小表达式热求值变化较小，64 变量链有较明显收益，16 变量 `and` 略慢约 0.3 ns，不能声称全部场景更快。此处只测布尔组件，不包含正则匹配、I/O、UI，也未覆盖所有混合表达式性能或运行同源码双二进制控制，不据此承诺整应用倍速或所有平台绝无退化。单变量操作名称对应相同代码，其创建耗时也有顺序偏差，说明不应过度解释纳秒级差异。

独立插桩中两版所有测量项热求值均为零次 glibc 分配请求；不包含 mimalloc、mmap 或峰值内存。原始结果保存在本地忽略目录 `out/benchmarks/p6-boolean/results-final/`，含 checksum、CPU、二进制 SHA-256 和逐轮样本；永久仓库保留兼容性 fixture 和复现工具，不提交平台二进制。完整方法见 [探针说明](../../../tools/benchmarks/boolean_evaluator/README.md)。
