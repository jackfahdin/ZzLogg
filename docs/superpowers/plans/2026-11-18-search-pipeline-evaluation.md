# P11：生产组件搜索探针实现计划

> **面向 AI 代理的工作者：** 使用 executing-plans 逐任务执行；沿用用户已确认的优化路线、本地 master 中文提交、不推送。

**目标：** 验证 memchr 的内核收益在生产转码、布尔求值及结果收集成本下是否仍有价值。

**架构：** 显式可选探针链接真实 `klogg_logdata`／`klogg_regex`；Qt 参考调用真实 `RegularExpression`／`PatternMatcher`。候选复用前轮 `LiteralMatcher`，以 1／128／4096 行批次生成子模式位图，再调用生产 `BooleanExpressionEvaluator` 和 Roaring 结果容器。只生成受控查询，绝不复制生产查询解析器。

**技术栈：** C++17、项目 Qt 6.10+、锁定的 Rust memchr 2.8.3；Cargo offline/locked。

**规格：** [既定路线 P11](2026-11-13-dependency-performance-roadmap.md#p11-纯文本和多关键词) 与 [前轮结论](2026-11-16-stringzilla-evaluation.md)。本记录是该已授权下一步的细化。

## 设计边界与方案

直接接入应用会提前引入工具链及行为变化；只重复内核实验回答不了接口问题。采用链接生产组件的独立探针，沿用前轮候选适配，保持生产代码和默认构建依赖不变。这是代理根据既定目标选择的实验方法。

计时包含 RawLines 转码／分行、候选编码验证、布尔求值、行号收集和最大宽度统计；不包含磁盘索引、TBB 图调度、高亮或 UI。单行候选包含现有通用批次适配的分配，不代表已优化的最小 FFI 接口。编码覆盖 UTF-8、UTF-16LE、Latin-1、异常 UTF-8；测试预过滤、CRLF、尾行及 NUL。

取消仅做单线程批次边界模型：预先取消不开始转换；在首批开始后注入请求，当前批次完成后退出。报告已处理行数和独立诊断中的最长批次服务时间；不宣称实际 TBB／UI 取消延迟。热计时不夹带每批时钟采样。峰值 RSS 在新进程单案例诊断，包含输入、Qt 和运行时，不当作候选净分配。

合成日志可复现；真实用户日志、端到端后台任务、加速后端和 Windows／macOS／ARM 原生验证继续待办。

## 2026-11-18 结果与决定

**memchr 值得继续进入完整后台任务的可选实验，但本轮不接入生产。** 转码／分行、布尔求值和结果容器没有抵消这批合成输入上的收益；逐行通用适配也仍有明显收益。另一方面，回退场景没有稳定收益，部分变慢，不能把所有查询绕过一次通用适配再统一交回 Qt。后续应将不合格查询直接路由到现有 PatternMatcher，并测量异常行的混合比例和完整后台取消／进度行为。

128 行批次可作为后续实验起点：短行单关键词减少了通用逐行适配成本，而本轮大多数长行多模式场景中 128 与 4096 差别很小。此处不确定最佳批量大小；还需要按字节限制、超长行及真实日志测量，也不据此扩大生产依赖。

### 方法与环境

Linux x86_64、Intel Core i7-14700，CPU 0、未锁频，Qt 6.11.1、GCC 15.2.0、rustc 1.100.0、memchr 2.8.3。复用主工程 Release 构建，LTO OFF、WARNINGS_AS_ERRORS ON；继承主工程的 `-O3 -DNDEBUG`、`-march=native -mtune=generic` 等选项。前轮独立内核工程没有同一套选项，不横比两轮绝对耗时。

32 场景 × 4 个候选（含 Qt 同实现控制）× 4 轮 × 每轮 4 个 ABBA 热记录，共 **2048 条热记录**；另有 **128 个新进程单案例诊断**。每侧每场景八个热样本、四次独立构造和首次扫描。28 个合格场景包括常规输入与预过滤／压力场景；4 个回退场景另列。全体首扫完整结果与诊断结果摘要、跨轮输入摘要一致。热循环消费数量／宽度／处理量校验和，未逐遍做完整 SHA。

下表是配对 Qt 耗时中位数除以候选耗时中位数；大于 1 表示候选快。跨场景分布只描述本实验，不能当作整应用倍数。

| 候选 | 合格场景最小／中位／最大 | 回退场景最小／中位／最大 |
| --- | ---: | ---: |
| memchr，每次 1 行 | 2.393 / 19.566 / 181.153 | 0.827 / 0.926 / 1.041 |
| memchr，每次 128 行 | 3.193 / 20.916 / 140.941 | 0.868 / 0.926 / 0.966 |
| memchr，每次 4096 行 | 3.168 / 20.848 / 176.197 | 0.945 / 0.992 / 0.999 |
| Qt / Qt 控制 | 0.911 / 1.020 / 1.171 | 0.961 / 0.977 / 1.042 |

Qt 控制说明本机仍有约 -9%～+17% 的场景波动，不用微小倍率差给候选排名。回退最差样本为逐行适配的空模式查询：Qt 2517 ns／行，候选 3044 ns／行，耗时约增加 21%。这不是 memchr 查找内核变慢，而是该查询完全回退后仍经过实验适配；不能忽略这项集成成本。

### 代表场景的候选耗时

单位 ns／行，包含该行全部模式求值和结果收集，亦摊入该块的转换／分行成本。三列来自各自配对过程；相近值不作精细排序。

| 场景 | 逐行 memchr | 128 行 memchr | 4096 行 memchr |
| --- | ---: | ---: | ---: |
| ASCII 128 字节，1 模式 | 42.83 | 23.83 | 27.16 |
| ASCII 4096 字节，64 模式 | 5240.83 | 5197.36 | 5181.47 |
| UTF-16LE 转码，4096 UTF-8 字节，64 模式 | 5846.22 | 5934.62 | 5944.43 |
| 预过滤，16 模式 | 445.33 | 438.34 | 437.50 |
| 长公共前缀，64 模式 | 4443.80 | 4461.58 | 4473.02 |
| 高重叠，64 模式 | 1147.13 | 1128.43 | 1141.01 |
| 8193 个短行，64 模式 | 491.93 | 462.83 | 463.61 |

例如 128 行候选在 ASCII 长行／64 模式的配对 Qt 为 248108 ns／行，在 UTF-16LE 场景为 161745 ns／行；这些合成数据中的正则匹配占比很高，收益不能推广到磁盘瓶颈、UI 或真实用户工作负载。

构造也不等于纯 Finder 初始化。以 ASCII 长行／64 模式为例，128 行候选构造 0.764 ms、首次 512 行扫描 2.700 ms；对应 Qt 为 0.753 ms、128.475 ms。UTF-16LE 下候选构造 0.827 ms、首次 7.124 ms；对应 Qt 为 0.825 ms、80.052 ms。构造包含生产 `RegularExpression` 及其内部表达式验证；首扫包含新转换缓冲与首次 Qt JIT，非全新进程启动时间。

### 临时位图、RSS 与取消边界

以 8193 个短行、64 模式为例，以下是独立新进程诊断的一次采样。取消请求在首批刚开始后注入，表中服务时间只统计该批匹配／求值／收集，不包含转换、真实线程调度或 UI。

| 后端 | 最大子模式位图有效字节 | 注入请求后处理行数 | 首批服务时间 | 进程峰值 RSS KiB |
| --- | ---: | ---: | ---: | ---: |
| Qt，探针每 4096 行检查 | 0（不生成批次位图） | 4096 | 52.690 ms | 28584 |
| memchr 1 行 | 64 | 1 | 0.00135 ms | 28612 |
| memchr 128 行 | 8192 | 128 | 0.05886 ms | 28604 |
| memchr 4096 行 | 262144 | 4096 | 1.92030 ms | 29008 |

128 与 4096 的吞吐在此场景相近，但前者位图有效字节减少 32 倍、每次未观察取消的行数更少。RSS 是整个进程高水位，包含合成样本、缓冲、运行时及同时保留的诊断结果；只有一次诊断，不能把数百 KiB 差距当成精确净内存差。位图也未统计 capacity、ByteView 或其他分配。

UTF-16LE 长行／64 模式在 memchr 128 的诊断中，转换约 0.949 ms，首个 128 行批次约 0.690 ms；memchr 4096 实际一批 512 行约 2.763 ms。转换仍不可中断，单个超长行也不能靠限制行数保证取消延迟。实际生产 worker 的取消检查、TBB 排队和进度发布没有改动，本轮没有实际应用取消延迟结论。
