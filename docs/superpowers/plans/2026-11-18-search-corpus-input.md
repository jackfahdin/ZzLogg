# P11：外部日志语料输入与可复现对照

> 沿用 writing-plans / executing-plans；本地 master 中文提交，不推送。

**规格：** [高亮与路由验证的下一步](2026-11-18-search-highlight-routing.md)。目标是给真实日志提供可复现入口，不将构建日志等同于用户代表性负载，不切换生产后端。

## 方案

扩展现有 worker 探针和 runner，接受版本化 JSON 查询清单。每条 case 指定 id、file、encoding、pattern、kind（literal／regex／boolean-literal／boolean-regex），可选 case_sensitive、inverse、threads、chunk_lines、prefilter、timeout_ms。相对文件路径从清单目录解析；拒绝重复 id、未知字段／编码／查询类型和无效数值。

runner 在测量前流式复制只读源文件到临时快照，同一源文件只复制一次，记录 SHA-256 和字节数；发现源文件元数据在复制时变化即失败。输入应是停止写入的普通文件，复制不是文件系统原子快照。所有轮次和后端共用这些副本；不改源文件、不将日志正文放入结果。查询和本地路径属于本地复现信息，会出现在报告元数据中。

探针也用有界复制缓冲创建自己的临时文件，再调用真实索引和搜索；不把整个外部日志读入 QByteArray。数据准备和索引不计时。每个 case 的完整结果与 Qt 对照，复用四轮 ABBA 和 Qt 控制；输入摘要覆盖实际文件内容及全部影响结果的查询／任务配置，不能只用文件名标识语料。索引／搜索使用可配置软超时，runner 的进程超时是硬限制；不宣称单个 Qt 调用可被即时打断。

保留生成样例模式；新入口仍只属于显式实验。不存在有效外部语料证据时，只报告工具／契约完成。可用当前本地构建日志检查实际文本文件流程，但代表性和跨平台准入继续待办。

## 审查重点

- 外部大文件不能全量装入内存；源文件不修改，清理只涉及本轮临时副本。
- 内容／模式开关／编码／prefilter／线程及块大小进入签名，跨轮输入不一致必须失败。
- 缺文件、非普通文件、坏清单／编码／查询和超时不能留下新的成功报告。
- Qt 结果校验和计时位置不变，外部日志只有热页缓存证据，不假称冷盘或首次打开性能。
- 默认程序与 CI 不新增 Rust 或外部语料依赖；生成样例入口仍可运行。

## 2026-11-18 结果与决定

**外部日志对照入口完成，默认应用与搜索后端保持不变。** 现在可以用日志文件和查询清单执行可复现对照；本轮只用已结束的本机构建／CTest 日志验收流程，尚未获得业务代表性语料，因此不授予生产采用准入。

### 输入与报告契约

源文件用 1 MiB 缓冲复制，runner 每个源文件只复制一次，并在各轮／后端复用固定副本；探针用流式副本执行真实索引。内容 SHA、字节数和全部查询／任务配置进入校验，发现内容／结果／场景覆盖／配对顺序不一致则非零退出。源日志、清单与报告之间有输出路径隔离。

独立审查发现已有输出文件可能通过软链接或硬链接指向输入，原来的 write_text 会截断输入。补充真实文件链接回归，先观察两类链接导致源内容改变，再将所有原始输出和最终报告统一改为“新建临时文件 → 替换目录项”，两类链接回归及真实 runner 的日志／清单硬链接保护都通过。超时会终止子进程并清理它的私有临时目录；正常输入、复制中增长、缺文件、目录、坏清单／编码／查询、重复 id、选项误用及超时都有验收。

完整结果验收使用固定行号和宽度推导 SHA，不仅比较命中数量。例如无换行尾行 `ERROR\nok\nERROR` 的命中行为是 0、2，最大字节宽度 5，处理位置 3；UTF-16LE 编码后得到相同结果。反选、布尔组合、大小写／语法／编码／预过滤／线程／块／超时配置也覆盖签名变化。

四种查询分别使用 1／2 个匹配线程，共 8 场景；两种候选（memchr 与 Qt 控制）× 四轮配对，共 **256 条计时记录、64 条诊断**。每次完整结果摘要一致，文件内容与 runner 快照摘要一致。额外用独立 Python 对这 8 个具体查询重新推导匹配行号、最大字节宽度和完整结果摘要，全部一致；16 组汇总均重新计算一致。

所有 64 条取消诊断都在全部结果发布后才收到请求（每文件不足一个 1024 行读取块），因此**本轮不提供有效的早期取消延迟证据**。存活块计数均归零，原有大样例取消契约仍单独通过。
