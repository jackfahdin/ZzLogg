# P9：文件监控行为基线与 Qt 候选对照

**基线：** `a507d42`。执行已确认路线，先证明行为再决定替换；本机只有 Linux，不能据此宣称三平台等价。

**范围：** 增加真实生产 FileWatcher 的回归测试，与独立 Qt 候选在同一场景下对照。候选仅编入测试和手动探针，不接入应用默认路径，不删除 efsw。验证本机可验证的全部场景，记录网络路径及 Windows／macOS 的待验证项。

## 设计

现有方案使用 efsw 目录监控、可选的大小／mtime 轮询、250 ms 合并。通知后 LogData 重新检查文件身份及摘要，决定追加索引或完整重建。测试把通知作为重新读取路径的触发器，而不要求每次写入都有唯一事件。

候选使用 QFileSystemWatcher 同时监控文件与父目录，文件事件触发路径重读，目录事件触发该目录已登记文件重读及重新注册；注册失败或目录消失时由周期检查重试。独立轮询对照与现有大小／mtime 规则对齐。保留 250 ms 合并；不在通知层加入全文摘要，避免把高成本扫描当作免费兜底。

方案取舍：直接只监控文件最简单，但删除／原子替换后会失去监控；文件加目录并重试能恢复路径，代价是更多监控项与自维护状态；继续 efsw 则保留已有原生实现与平台覆盖。根据行为证据决定下一步，不预设替换结论。

## 结果

**决定：保留生产 efsw。** 本轮完成 Linux 行为基线和独立候选评估，没有替换应用实现，也不标记整个 P9 完成。efsw 当前受跟踪源码为 108 个文件、386,533 字节（约 377.5 KiB）；这点清理收益不足以跳过平台与集成验证。

### 行为结果

Linux 本地临时目录，native／poll／hybrid 分别指原生通知、纯轮询、两者并用。以下“通过”仅适用于本轮场景和观察窗口。

| 场景 | 生产 efsw | Qt 候选 |
| --- | --- | --- |
| 追加、截断、同尺寸且 mtime 改变的覆盖 | 三模式通过 | 三模式通过 |
| 文件轮转、删除重建、原子替换及后续追加 | 三模式通过 | 三模式通过 |
| 同尺寸且恢复原 mtime 的覆盖 | native／hybrid 检出；poll 漏检 | native／hybrid 检出；poll 漏检 |
| 重复登记后移除 | 通过 | 通过 |
| 父目录删除后重建 | native 在 3 秒内未恢复；poll／hybrid 恢复 | 三模式恢复 |
| 登记时父目录不存在，随后创建 | native 在 3 秒内未恢复；poll／hybrid 恢复 | 三模式恢复 |
| 实际 LogData 更新行数与内容 | 三模式通过 | 未集成，未验证 |

父目录恢复场景是 `recoveryReport` 诊断输出，必须读取 `WATCH_RECOVERY` 的布尔值，不能把 QtTest 方法执行 PASS 当作恢复成功。纯轮询依赖文件大小和毫秒级 mtime，同元数据覆盖是现有盲区；本轮没有添加全文扫描兜底。

应用默认所有平台开启原生监控，Windows 默认额外开启轮询、其他平台默认关闭轮询，默认轮询周期为 2000 ms。本轮测试与候选统一使用 100 ms，通知合并窗口为 250 ms，不能直接推导默认配置的延迟。

### 采样结果

Linux x86_64、Qt 6.11.1、GCC 15.2.0，复用 Release 构建。128 个文件位于同一目录，静置后采集 2 秒空闲进程 CPU，再每 20 ms 写入一次、持续 2 秒。执行一次 ABBA，每版每模式 2 份样本，下表为中位数。

| 实现 | 模式 | 2 秒空闲 CPU（ms） | 持续写入通知数 | 最终内容通知延迟（ms） |
| --- | --- | ---: | ---: | ---: |
| efsw | native | 6.700 | 7 | 75.5 |
| Qt 候选 | native | 7.247 | 7 | 75.5 |
| efsw | poll | 9.491 | 6 | 177.0 |
| Qt 候选 | poll | 7.831 | 6 | 126.5 |
| efsw | hybrid | 8.496 | 7 | 75.5 |
| Qt 候选 | hybrid | 11.088 | 7 | 75.5 |

两者均能周期通知并送达最终内容；没有足够证据证明 Qt 候选整体更快。CPU 包含 QtTest 开销，未固定 CPU 或锁频，样本很少；最终延迟受写入时刻与合并窗口相位影响。没有测量完整索引吞吐、UI 渲染、内核资源上限或跨平台性能。

复现与测量说明见 [探针 README](../../../tools/benchmarks/filewatch/README.md)。本地原始日志与元数据位于 `out/benchmarks/p9-filewatch/results/`（不提交构建产物），探针 SHA-256：`8ba9c9fe078c5ac54790a200bc33e686f6490c2b7c09c1b213a757632e66dfce`。
