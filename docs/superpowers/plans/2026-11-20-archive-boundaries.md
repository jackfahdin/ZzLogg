# P13 归档输出边界加固

> 使用 writing-plans／executing-plans 内联执行，最终一次独立审查。

**目标／规格：** 延续用户确认的下一步：在真实 Decompressor 及隔离临时目录中验证归档路径、链接和资源边界，修复确认的越界／既有文件破坏问题。保持常规 ZIP／tar／7z 与目录内部相对链接可用，不添加任意日志大小限额。现有 UI 在私有 QTemporaryDir 中解包；本轮防归档内容和静态目标链接，不宣称跨平台原生验证或对抗同权限进程并发换目录的无竞态沙箱。

**方案：** 在 vendor KArchiveDirectory::copyTo 中先遍历完整树，验证单个成员名、目录类型、负长度／总量整数溢出、相对链接解析后仍在根内，并拒绝目标路径已有的符号链接／特殊文件。通过后创建目录、复制普通文件，最后创建内部链接，且链接创建失败返回 false。KArchiveFile::copyTo 使用 QSaveFile 原子替换，拒绝链接／特殊目标，避免截断既有硬链接所指向的目录外文件。沿用按数据偏移读取与有界复制缓冲、取消。Qt 路径检查符合当前私有目录模型，不增加一套平台特有解包器。

**文件：** vendor karchive.cpp（必要的短长度校验在 ktar.cpp）；新增 tests/ui/archive_safety_test.cpp 与独立 fixtures/archive-safety，CMake 注册；现有 archive_test 的 /dev/full 符号链接用例明确改作链接拒绝语义，流式 flush 错误已有专门回归。优化文档和 vendor 补丁记录更新。顺手补齐上一轮明确登记的 fork 流诊断复跑命令。

**2026-11-27 接续：** 上次会话在独立审查中断，未提交。遗留审查指出链接表按精确字符串查找，与大小写不敏感文件系统可能不一致。本轮增加 tar／ZIP 的大小写别名、Unicode 组合／分解别名和同名输出回归，原实现八项均错误接受并创建输出；统一采用 NFC 规范化、case folding、再 NFC 的路径键拒绝输出冲突，链接解析拒绝非精确拼写的别名，保留精确拼写的内部相对链接与链。此规则在 Linux 同样生效，代价是原本在大小写敏感文件系统上合法的大小写不同成员也可能被拒绝；这些可移植策略测试不能代替原生 macOS／Windows 验收。

## 审查重点

- ../、同名前缀兄弟目录、平台路径形式不能越界；失败时预先存在的哨兵内容不变，普通绝对 tar 路径按既有解析行为仅在根内相对化。
- 外部／间接链接、已有目录链接、文件链接、悬空链接及硬链接不能使复制修改根外文件；内部相对链接与链仍可用，链接最后创建。
- 错误长度和总量溢出在输出前拒绝；合法大文件不受固定上限影响，取消不创建输出。
- Qt 安全保存不回退为直接截断；原子提交失败及链接创建失败返回 false，原有普通文件可正常替换。
- 私有临时目录的信任边界、未验证的并发竞态和原生 Windows 行为如实记录。
