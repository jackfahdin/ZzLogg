# P12：直接 UTF-8 正则的完整后台搜索实验

> 使用 executing-plans 内联执行；沿用已授权的本地 master 中文提交，不推送。

**目标：** 验证独立 PCRE2-8 候选在真实 LogFilteredDataWorker 中的结果、完整耗时、首批通知、取消与资源释放。默认应用、Qt 高亮和已选加速后端保持原行为。
**规格：** 延续 `../specs/2026-11-19-utf8-regex-probe-design.md` 的语义及回退要求。
**架构：** 复用现有实验 worker 副本；构建时选择 memchr 或 PCRE2-8。每个匹配线程持有独立候选与 scratch，保留 128 行／256 KiB 批次及超长行 Qt 回退。PCRE 构建不要求 Rust。

## Task 1: 接入、验证和测量

1. 增加实际 worker 的正则、布尔、回退及生命周期契约，确认未接入候选时路由断言失败。
2. 复用独立组件的 PCRE CMake 配置，接入实验批匹配；增加路由／代码成本、live matcher 和首批通知诊断。
3. 扩展现有测量器选择候选、逐场景独立进程资源诊断；生成 Android 模拟语料查询与独立完整结果预期。
4. 验证 PCRE／memchr worker、实际 Vectorscan 选择优先级、高亮、Python CI 和组件契约；检查默认构建隔离。
5. 一次最终独立审查；空闲负载下四轮 ABBA／BAAB 与 Qt 控制，记录证据及局限。
6. 更新本文和路线图，中文提交。

Expected: 全部固定结果及独立预期一致；取消后 live block／matcher 为零，重新搜索完整；PCRE 路由得到实际计数证明；不把组件倍率外推为应用倍率。

## 测量口径

计时从 search 提交前到取回结果、销毁 worker 并 join；索引在计时外。首次进度是主线程收到非终态进度信号，首次命中是收到累计命中数非零的信号，不代表 GUI 绘制。取消延迟从收到首个非终态通知并请求 interrupt 到完整销毁；单次 Qt／PCRE 调用不可中断。资源诊断在计时之外，每场景新进程的峰值 RSS 包含 Qt 参考、索引、全量／取消两次搜索及共享库，不能当候选内存增量。

## 审查重点

线程间不能共享 PCRE scratch；位图顺序须保持真实布尔／反选语义；坏编码、BOM、\\C 和超长行正确回退；取消／更新后释放所有实例；首批通知和峰值 RSS 不夸大；memchr 现有工作流及默认构建不新增依赖；报告核对完整结果、线程数、实际路由和输入摘要。

## 完成结论（2026-11-19）

**保留实验，不默认启用 PCRE2-8。** 完整 worker 中，16 条正则的应用日志查询保留了约 6.3～6.7 倍收益；多种单正则查询接近持平，双线程部分查询约快 1.47～1.55 倍。首次命中和取消也没有统一改善。按减少依赖／维护复杂度的优先级，证据支持先检查现有管线调度，再决定是否值得新增另一套 PCRE。

本轮完成计划全部步骤；不修改生产源码或默认后端。实验开关只影响克隆的 regex／logdata 目标；构建时选择 PCRE2 或原 memchr，新建 PCRE worker 构建图不出现 Cargo／Rust。PCRE 源码仍显式取自本机 Qt 配套的 10.47，不下载、不复制 vendor、不调用 Qt 私有构建函数。单独组件与 worker 共用同一份 PCRE 构建配置。

### 语义、路由和所有权

- 每个真实匹配节点持有自己的 PCRE 实例、match data/context 与 JIT stack，节点并发度为 1；没有跨节点共享可变 scratch。
- 每批仍最多 128 行／256 KiB，行优先位图交给现有布尔求值和反选逻辑。零长度匹配、正则布尔／反选、大小写、Unicode、BOM／坏字节、NUL、UTF-16LE／Latin-1、范围、追加尾行移除、预筛选与空文件契约通过。
- `\C` 按模式回 Qt；BOM／坏 UTF-8 按行回 Qt；超长行使用 worker 原有 Qt matcher。固定两线程布尔查询实际生成 4 个 PCRE/JIT 程序、执行 10 次直接匹配；代码单元查询实际走 Qt。
- 正式主日志全部 PCRE 模式生成 JIT，所有诊断运行错误为零。16 模式查询每次全量搜索有 1048576 次直接匹配；双线程只是每线程分别编译，不重复扫描输入。
- 边界文件的 12 行中有 2 行超过 256 KiB；这些行完全走原 Qt。其余 10 行的普通模式为 8 次直接／2 次编码回退；代码单元模式为 0 次直接／10 次回退。不能用上轮组件处理超长行的收益代表本轮 worker。
- 完整搜索、取消及重新搜索、预取消、追加更新后的 live matcher／block 都归零；固定结果和完整摘要一致。这是实例所有权检查，未声称完整 worker 做过堆泄漏检测。
- 真实 Qt 高亮／quick find 坐标继续通过；实际 Vectorscan 单／多模式与 worker 选择优先级通过，启用实验不会抢占已选加速引擎。

### 正式测量

使用既有 Android **模拟** dmesg、logcat、应用日志各 65536 行及 12 行边界，共 24938730 字节。输入内容及 SHA 与 Android 语料记录一致。10 类主日志查询和 5 类边界查询，各配 1／2 匹配线程，共 30 场景；chunk 为 1024 行。包括单正则、大小写、环视、16 模式布尔 OR、布尔 AND NOT／反选、未命中、代码单元回退。

四轮交换进程顺序与 ABBA／BAAB，包含 Qt/Qt 同实现控制。共 **960 条完整 worker 计时、240 条独立进程诊断**，全部 1200 条结果／文件／查询配置摘要通过独立 Python 预期核对。每个场景／角色有 8 个计时样本；程序构造、工作线程启动、匹配、结果收集、销毁／join 均在计时内，索引和输入副本在计时外。每次重新构造 matcher，含编译与 JIT 成本，不是持久 worker 的热正则扫描。

环境：Linux x86_64、Intel Core i7-14700、CPU 0／1、Qt 6.11.1、GCC 15.2、Release、LTO OFF、未锁频；Qt JIT 环境设为 1，PCRE 逐程序查询实际 JIT 字节。正式测量无并行构建／测试／调试器负载；此前冒烟期间有并行构建，冒烟耗时不作证据。

### 资源成本

每场景／后端／轮次使用新进程采集峰值 RSS，进程包含文件索引、Qt 参考、候选完整／取消两次搜索、TBB、Qt 共享库与分配器。主日志逐场景的峰值 RSS 中位数，Qt 为约 **40.46～67.14 MiB**，候选为 **40.57～60.82 MiB**。不同场景有增有减，不能据此声称候选省内存，也不能用两者相减代替候选分配量；需要更细的分配诊断才能归因。

16 模式场景单线程 PCRE 编译代码 3097 字节、JIT 13670 字节；双线程合计 6194／27340 字节，峰值 live matcher 分别 1／2。这些计数不含 Qt 回退正则／原 matcher、match data/context、JIT stack 和其他 worker 数据。每实例 JIT stack 初始 32 KiB、最大 512 KiB；最大值是容量上界，不是实测常驻量。现在确实同时保留 Qt 和额外 PCRE 状态，不能称为零维护／零内存新增。
