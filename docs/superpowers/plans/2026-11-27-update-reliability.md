# Windows 自更新可靠性实现计划

> 执行方式：executing-plans，当前工作区内联实现。用户授权自行选择方案；保留现有分支和构建缓存，完成后独立审查。

目标：下载之后，只有安装验证通过且新程序响应才报告成功；失败保留可定位的日志及恢复资料。

架构：沿用签名、安装身份、进程认证、退出门禁及现有事务。借鉴 snow-shot 的提交前启动探测，把探测失败纳入回滚。探测必须绕开单实例、安装锁及真实用户设置。安装版和便携版共用原生探测/重启检查；不引入 Rust 工具链。

约束：不更改公共 feed / 签名协议；不改 macOS、Linux 更新行为；不把交叉编译当作 Windows 验收。用户故障尚无日志，已确认的代码缺陷不等于已定位该机器的唯一根因。

## 任务 1：隔离启动探测与事务回滚

- [x] 测试真实应用 `--update-probe`：成功标记、错误参数拒绝、用户配置目录不变；原实现应失败。
- [x] 在 main 入口拦截探测，仅初始化 Qt 平台、临时存储、主题和隐藏控件，不进入 KloggApp 生命周期。
- [x] 为 portable replaceFiles 增加提交前验证回调；用完整替换后的失败证明新建文件删除、旧文件及删除项恢复、用户文件不变。
- [x] TxEngine 添加验证钩子，生产绑定有界原生探测；失败走现有日志和注册表/文件回滚。
- [x] 原生探测测试覆盖正常、退出码失败、无标记、超时，以及路径空格。

## 任务 2：重启结果与诊断

- [x] 便携版等待新进程存活及目录对应的单实例端点，禁止 CreateProcess 成功即写 complete。
- [x] 安装版 relay 按阶段落盘结果，包含子进程退出码；失败重启必须等引擎确实退出。
- [x] 使用正确的 Windows 参数转义，保留数据目录；原生测试覆盖即时退出和未就绪。

## 任务 3：验收与审查

- [x] 增加可运行的两个本地版本验收：原应用退出、新 PID 响应、版本更换、数据保留、日志结果；缺少 Windows 环境如实记为未验证。
- [x] Linux ci_build + 全套 ctest；MinGW 编译涉及的原生组件及测试。
- [x] 独立审查并修复重要发现。记录 Windows 原生验收剩余条件，不宣称用户故障已彻底解决。

审查重点：探测绕开安装锁但不能访问真实设置；探测进程退出后才能回滚；DLL/插件缺失必须失败；事务失败不能冒报重启成功；旧版向新版本更新时协议兼容。


## 验证记录与剩余条件

实现已完成，独立审查发现的就绪信号挂点、活动日志共享权限问题均已修正，并补真实主实例就绪测试。就绪确认采用 PID 对应 StartupReady event + 单实例端口 + 进程存活，强于原先只看端口。

本地已运行 Linux ci_build、93 项 CTest、124 项 Python 测试（3 项按既有条件跳过）。MinGW 编译涉及的 Windows 原生源文件，并链接启动检查测试及三个生产更新器（ZzLoggUpdate、ZzLoggUpdateTx、ZzLoggPortableUpdate）。现有 LTO ODR / MinGW NOMINMAX 警告仍存在。

**未完成的环境验收：** 当前 Linux 主机没有 Windows 运行环境，Windows 原生 CTest、PowerShell 验收器和两个实际版本升级尚未运行。上面的“验收入口已实现”不是“真实升级已通过”。最终发布前须按 docs/development/DESKTOP_UPDATE_ACCEPTANCE.md 的 Windows 步骤得到 PASS，并补测正式旧版本迁入；也须验证 Qt 平台插件缺失时回滚。不能据本地测试宣称用户机器上的下载后失败已彻底解决。

发布前复核进一步统一了 GUI、协调器和引擎的等待预算：GUI 覆盖包校验、安装器启动及准备阶段，引擎的交接等待覆盖协调器对应阶段及 IPC 余量；等待旧程序退出使用实际时钟截止时间。用户长期不处理 UAC 仍可触发安全超时，这不是无限等待承诺。提交前重跑 93 项 CTest、124 项 Python 测试（3 项条件跳过）及原生更新器交叉编译均通过；计划随 26.11.02 发布。
