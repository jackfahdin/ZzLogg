# 组合搜索高亮修复

目标：勾选“高亮匹配”后，组合搜索在原文和结果区高亮命中的文字。

采用独立的显示辅助器，复用已验证的搜索表达式拆分结果，仅计算应高亮的条件。沿用现有搜索引擎，默认开关保持现状。逐行检查组合逻辑，只收集成立分支中的正向匹配；纯排除条件没有可高亮文字，嵌套取反按实际逻辑处理。解析结果在搜索条件改变时准备，重绘时仅处理可见行。

不采用直接取消 isBoolean 判断的方式：这会把整个逻辑表达式当成一条普通正则，无法正确匹配。也不通过另外配置高亮规则来规避问题。

- [x] 查明组合模式被绘制代码直接跳过。
- [x] 添加实际画面回归测试，确认 and/not、or、分组、符号运算符和正则组合缺少高亮。
- [x] 添加 BooleanSearchHighlighter，覆盖与现有 ExprTk 一致的运算符优先级和分支语义。
- [x] 接入 AbstractLogView，验证主视图与结果视图、设置即时生效、清空搜索。
- [x] 执行定向测试、完整构建和全量回归，独立审查后收尾。

验证中发现两个相关问题并纳入修复：

- 帮助已声明支持的 `!(...)` 实际被 ExprTk 拒绝。只在引号内容提取后，把逻辑 `!` 规范化为 `not`，字符串里的感叹号保持原样；增加有效/无效匹配回归。
- 清空按钮原来仅修改输入框，未通知文本编辑处理链，因此旧高亮保留。让清空按钮触发已有编辑通知，并在文本为空时清理当前两个视图的搜索高亮；不主动重跑搜索或清空已有结果。
