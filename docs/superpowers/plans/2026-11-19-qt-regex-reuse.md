# P12：Qt 正则复用审计实现计划

> 使用 executing-plans 内联完成，最后一次独立审查；本地 master 中文提交，不推送。

**目标：** 核实 Qt JIT／编译复用，修复预筛选复核中的逐候选正则构建和重复解码。
**架构：** HsPrefilterMatcher 保存 matcher 私有 Qt 正则；每行按需解码一次。测试工具链接实际 klogg_regex，不引入生产诊断。
**技术栈：** C++17、Qt 6、既有 Vectorscan；可选本地 Python/GDB 诊断。
**规格：** `docs/superpowers/specs/2026-11-19-qt-regex-reuse-design.md`。

## 审查重点

误把预筛选假阳性当命中；候选掩码顺序；无候选时不解码；每次调用不能沿用上一行文本；matcher 不依赖源表达式寿命。真实固定样例及独立 matcher 重复调用验证这些行为，构造次数诊断覆盖热路径重编译。异常 UTF-8 不外推为 Vectorscan 与 Qt 的普遍等价。

## 审计结论

本轮采用 **HsPrefilterMatcher 的局部复用优化**，不替换 Qt 正则、不新增依赖，P12 直接 UTF-8 后端仍未实施。

| 路径 | 事实 | 本轮处理 |
| --- | --- | --- |
| 普通 Qt matcher | 构造时保存 QRegularExpression，热扫描复用；P5 已将逐行解码移到模式循环外 | 保持现状 |
| 查询校验／worker 创建 | 校验临时 Qt 正则与各 worker 新 matcher 仍可能分别编译；PatternMatcher 在选择 Qt 时还会替换先创建的 matcher | 不扩大本轮修改，未声称冷启动已最优 |
| Qt 6.11.1 JIT | 本机配套源码 compilePattern() 在模式变脏时编译并调用 optimizePattern()；后者依据 QT_ENABLE_REGEXP_JIT 等条件尝试 PCRE2 JIT | 不盲目增加 optimize()，不改变环境开关 |
| 加速预筛选 Qt 复核 | 旧实现每个候选行／模式都从字符串重新创建正则，再解码当前行 | 保存每个 matcher 私有 Qt 对象，候选行按需解码一次 |
| 高亮／原有搜索路由 | 本轮不改变这些实现和选项 | 使用实际组件契约回归验证 |

Qt 审计来自本地配套源码 `qtbase/src/corelib/text/qregularexpression.cpp`：compilePattern 约 886 行、isJitEnabled 约 975 行、optimizePattern 约 1002 行、optimize 约 1733 行。`optimize()` 是提前执行编译，不是额外一种搜索算法。默认 JIT 判断取决于 **Qt 库**的构建及运行条件；应用使用 Release 不能单独保证 JIT 成功。Qt 私有实现将来可能变化，不能当作跨版本接口承诺。

新缓存属于各 matcher，按首次候选命中惰性编译；没有全局共享缓存或新增锁。与旧版每次立即释放相比，会把已编译模式保留至 matcher 销毁，换取重复扫描复用；本轮没有测峰值内存，不承诺内存下降。无候选行不转 QString；候选掩码仍逐项由 Qt 精确复核，不能将预筛选假阳性直接发布。

## 正确性与重复工作证据

- 同一 GDB 诊断在旧代码上失败：预热后 64×4 行仍从 QString 构造 Qt 正则 **256 次**；新代码为 **0 次**。预热阶段分别实际观察到 4／2 次构造，证明断点工作；只说明模式对象复用，不能据此声称整个匹配零分配。
- 真实 Vectorscan `HsPrefilterMatcher` 验证多模式候选位序、正负向／后向环视、假阳性、中文／emoji、NUL、大小写、空行、重复调用，以及源表达式销毁后两个独立 matcher 仍可使用。加速后端测试 **3 项／66 条断言**通过，JIT 请求关闭时也通过。
- 既有实际 worker 的索引／进度／取消／重复搜索／编码／追加尾行契约，以及实际 Vectorscan 高亮／路由契约通过。
- 默认 Qt-only `ci_build` 完整构建和 **97/97 CTest** 通过；Python CI **136 项、3 项跳过、无失败**。
- 独立审查发现诊断在构造函数符号缺失时可能假通过。用不存在的符号复现“退出 0”的错误后，要求预热阶段必须观测到构造：缺失符号退出 1，旧实现退出 1（256），新实现退出 0（0），RED→GREEN。生产代码未发现重要审查问题。
- 两种构建目录的 all／ci_build 命令图均未引入新探针。GDB 是本地可选诊断工具，不是应用或 CI 的新增依赖。
