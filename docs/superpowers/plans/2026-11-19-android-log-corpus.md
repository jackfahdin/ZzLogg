# P11：Android 驱动开发模拟语料与对照

> 沿用 writing-plans / executing-plans；用户明确要求自行生成 dmesg、logcat 和 APK／应用日志。本地 master 中文提交，不推送。

**目标：** 生成符合 Android 驱动排障场景的确定性语料，直接用已有文件探针对照 Qt／memchr，并给出适用范围内的结果。

**方案：** Python 标准库流式生成三类主文件（默认各 65536 个物理行）及独立异常边界文件。固定种子和虚拟时间，改变 PID／TID、设备地址、返回码、任务、载荷，保留调用栈／崩溃多行关系。不要简单重复同一大段文字。语料明确标为 synthetic，不伪装设备采集。

查询覆盖 probe／I2C 超时、高频 irq、无命中、errno 正则、大小写回退；logcat 的 FATAL EXCEPTION、binder、包名、错误级别；应用中文、异常、JSON 长载荷、反选；边界文件的坏 UTF-8、NUL、CRLF、BOM、空行、无尾 LF 和超出 256 KiB 的单行。各查询使用 1／2 匹配线程，复用四轮 ABBA 和 Qt 控制。

生成时用独立 Python 谓词计算固定查询的完整命中行号／最大字节宽度／处理位置摘要，写 expected.json；不是从 Qt 或候选输出反推预期。结果验收检查所有计时／诊断条目的文件摘要及完整结果摘要、实际路由及超长行回退。查询只用两端共有的简单正则语法，Python 不被宣称为通用 Qt 正则参考。

## 文件与边界

- `scripts/dev/generate_android_search_corpus.py`：数据、清单、生成参数／内容摘要、独立预期与报告验收。只接受空输出目录，不覆盖已有日志；仅用标准库。
- `tests/ci/test_android_search_corpus.py`：固定小样本预期、可复现性／种子变化、物理行数、异常边界、输出保护、损坏报告拒绝。
- README、本文和路线图：复现命令、实际规模／命中分布、数据结论及局限。大型语料／结果放 out，不提交。

本轮不改变生产搜索、不新增运行依赖。热页缓存、生成分布与单机结果不代表真实设备、冷盘或跨平台；取消请求若到达过晚必须明确报告。

### 完整结果及耗时

17 个查询分别用 1／2 个匹配线程，共 34 场景；四轮交换候选进程顺序和 ABBA／BAAB 次序。**1088 条计时、272 条诊断**全部通过独立 Python 预期：完整行号／最大字节宽度／处理位置摘要、文件内容、预定查询配置、命中数、两后端／轮次覆盖、路由及资源限制一致。68 组汇总从原始记录重新计算一致。

判断：

- 三类主日志中，合格单线程查询倍率为 0.990～1.689，中位数 0.999：除应用多关键词外，基本没有收益，部分略慢。双线程为 1.025～3.898，中位数 1.494；其中 irq／无命中／probe 仅约 2.5%～3.4%，不能与明显收益混为一谈。
- 主日志的 Qt／Qt 同实现控制为 0.918～1.041；应用多关键词单线程控制偏离约 8%，因此不夸大精确倍率。正则／忽略大小写直接 Qt 的实测倍率为 0.998～1.012，没有实质收益。
- 12 行边界文件波动明显，Qt 控制为 0.397～1.396；候选最差 0.374，空模式直接 Qt 却出现 2.554。因此这组只能证明本轮输入正确性与路由，不能据其数字认定某算法稳定加速或退化。没有丢弃这组不利数据，也没有靠重跑挑选更好的结果。
- 全部诊断存活块为零，最大实际批次为 128 行／25456 字节，未突破 128 行／256 KiB 限额。边界合格查询各有两条超长行交由 Qt。`batched_rows` 包含进入适配后再回退 Qt 的坏编码行，并非全为 Rust 执行。

### 取消与验证

主日志的两后端各 112 条取消诊断全部在完整处理位置到达之前请求并退出；Qt 返回处理位置 1024～3072，候选 1024～8192（不保证是连续处理行数）。请求到任务释放的最小／中位／最大耗时分别为 Qt **0.565／0.901／1.012 ms**、候选 **0.697／1.038／1.117 ms**。本轮候选取消延迟没有优势，数据也不是延迟上界。边界文件 48 条诊断全部在完整结果发布后才请求取消，不作为有效早期取消证据。

- Python CI **136 项、3 项跳过、无失败**；新增 5 项覆盖独立固定结果、谓词、确定性／异常字节、输出保护及报告损坏。
- 真实文件入口／错误／超时／快照／链接保护契约通过；既有完整 worker 契约在 runner 开始时通过；Qt-only 和实际 Vectorscan 高亮／路由契约通过。
- 先用 1024 行／类的语料完成 34 场景冒烟：272 条计时、68 条诊断与独立预期一致。这组规模小，不用于性能结论。
- 独立审查发现“仅检查查询摘要跨轮一致，未绑定预定查询”的缺口；新增全报告一致但错误摘要的拒绝测试，确认 RED→GREEN，并通过完整 Python 套件。修复后全部正式记录的查询摘要与生成器独立构造的版本化配置摘要一致。没有遗留重要审查问题。
- 本轮未修改生产源码，复用前轮已验证的 C++ 二进制，没有重新构建默认应用或重跑其 97 项 CTest；不将前轮结果冒充本轮执行。
