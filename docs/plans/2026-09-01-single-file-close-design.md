# ZzLogg 单文件关闭设计

## 背景与根因

当前 `TabbedCrawlerWidget` 在标签数小于等于 1 时隐藏整个标签栏。关闭模型本身允许从一个文件变成零个文件，菜单“关闭”和 `Ctrl+W` 也能正常工作；但唯一标签被隐藏后，用户看不到标签关闭按钮、右键菜单和中键关闭入口，因此表现为“只有一个文件时无法关闭”。

UI2 只装饰现有 `MainWindow`，继续复用该标签组件，所以旧 UI 与 UI2 都受影响。

## 目标

- 只有一个文件时仍显示标签和关闭按钮。
- 鼠标、菜单和 `Ctrl+W` 都能关闭最后一个文件。
- 关闭后窗口保持打开，进入零文档空工作区。
- 两个文件关闭到一个文件后，剩余标签仍然可见、可关闭。
- 不改变窗口右上角关闭按钮和最小化到托盘语义。

## 行为设计

标签栏可见性规则改为：

- `count() == 0`：隐藏标签栏。
- `count() >= 1`：显示标签栏。

关闭最后一个文件后的既有清理流程保持不变：

- `currentIndex()` 变为 `-1`。
- 清空当前文档 signal mux、快速查找绑定、路径栏和标题中的文档名。
- 禁用依赖当前文档的编辑动作。
- 从窗口 session 和全局打开文件映射中移除该文件。
- 主窗口继续显示。

不新增工具栏关闭按钮，也不让窗口右上角 X 承担文档关闭功能。用户已经熟悉的标签关闭入口在单文件状态下保持可见即可。

## 实现边界

共享组件 `TabbedCrawlerWidget` 负责唯一的标签栏显隐规则。`MainWindow::closeTab()`、`Session::close()` 和 UI2 Fluent shell 不需要改变业务语义。

为便于测试，显隐更新应集中为一个小函数，在添加和删除标签后调用，避免未来再次出现 `> 1` 与 `<= 1` 不对称条件。

## 测试策略

- 添加第一个文档后，标签栏可见且第 0 个标签有关闭入口。
- 点击唯一标签的关闭入口，`tabCloseRequested(0)` 到达 `MainWindow`，最终标签数为 0。
- 两个文档关闭一个后，标签栏仍可见。
- 唯一文档分别通过标签按钮、菜单和 `Ctrl+W` 关闭后：标签数为 0、当前索引为 `-1`、路径和文档标题清空、窗口仍打开。
- 关闭最后文档后重新打开相同路径，不会被误判为已经打开。
- UI2 窗口 X 继续关闭窗口或按设置最小化到托盘，不作为文档关闭动作。

## 验收条件

- 单文件状态拥有明确可发现的鼠标关闭入口。
- 关闭最后一个文件不会退出程序。
- 现有多标签、菜单、快捷键、会话保存和 UI2 标题同步测试继续通过。
